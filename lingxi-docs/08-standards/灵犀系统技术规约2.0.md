## 一、整体原则

### 1.1 十条工程原则

| # | 原则 | 工程含义 | 违反判定 |
|---|---|---|---|
| P1 | **文档即权威** | `docs/` 五件套是唯一事实源；代码与文档冲突时**默认代码错** | 无契约先行开发；文档缺失即派发开发任务 |
| P2 | **契约先行** | 任何对外能力先冻结 OpenAPI 3.0 契约，再写实现 | 先写 Controller 后补文档 |
| P3 | **双通道同源** | 人工操作与智能体执行走**同一套 Service、同一张表** | 存在 `/api/agent/**` 绕过业务校验的写接口 |
| P4 | **边界即纪律** | 模块只经 API 契约与领域事件通信；禁跨模块直连数据库 | 出现跨模块表 JOIN |
| P5 | **配置外置** | 连接串、密钥、模型名、外部地址全部走配置 | 代码中出现 IP / 密码 / Key / 模型名 |
| P6 | **环境即代码** | 环境启停/迁移/体检/发布全部脚本化且幂等 | 存在非脚本化的环境操作 |
| P7 | **强类型全链路** | Java 静态类型 + JSpecify + TS strict + OpenAPI 生成类型 | 前端手写接口类型；Java 滥用 `Object` |
| P8 | **最小依赖** | 能用已有组件承载就不引入新中间件 | 引入一期"不引入清单"中的组件 |
| P9 | **安全不可委托** | 安全靠架构约束 + 自动化门禁 + 人工红线，不靠 AI 写对 | 敏感代码无人工 Review 即合并 |
| P10 | **可验证优先** | 每个交付物都必须有可自动执行的验证方式 | 新增接口无测试用例；新增租户数据接口无隔离用例 |
| P11 | **跨产品依赖只走 api** | 灵犀集群调用元枢一律经目标模块 `api` 包；元枢禁止依赖灵犀业务域 | `com.yuanshu..` 依赖 `com.lingxi.{业务域}..`，或集群直连元枢非 `api` 包（ArchUnit 两条方向规则机器校验） |

> **P3 与 P9 是本规约的底线条款**：前者保护数据一致性，后者保护商业交付资格。违反这两条直接阻断合并。
> **P11 是「一底两翼」的底线条款**（架构规划 §4 硬约束 1/2）：元枢不承载业务、集群不建第二套底座能力。

### 1.2 规约效力与执行机制

| 机制 | 说明 |
|---|---|
| **CI 门禁** | ArchUnit 依赖校验 · Checkstyle/ESLint · 覆盖率门禁 · 契约测试 · 硬编码扫描 · 租户隔离套件——机器可查的规则全部自动化阻断 |
| **代码评审** | 模块 Owner 制；【强制】项是评审必查项，打回需注明规约条款号（如"违反 4.4.3"） |
| **红线冻结** | 三条不可自动合并红线（见附录 E）：命中即冻结 PR，必须人工 Review |
| **规约仲裁** | 异议提交架构组周会裁决；规约变更走 RFC，公告后生效 |
| **每季度** | 规约符合度抽查 + 死规则清理（不再执行的条目删除或降级，保持规约可信） |

### 1.3 AI Coding 适配原则

| # | 原则 | 说明 |
|---|---|---|
| A1 | 任务分级执行 | T1 核心功能 / T2 修复与对接 / T3 测试与文档 / T4 数据与集成适配器 / T5 重构与架构调整 |
| A2 | **T5 禁止 AI 自主** | 重构与架构调整必须先由人设计，再拆为 T1/T2 执行 |
| A3 | 任务边界排除 | AI 任务边界**永不包含** `docs/`、`config/`、迁移脚本的已发布版本 |
| A4 | 唯一写入者 | 任务清单 `TASKS.md` 由协调 Agent 唯一写入，AI 开发工具只读 |
| A5 | 不信自报 | 验收由独立于开发方的流程执行，不采信开发方自报结果 |
| A6 | 修复上限 | 同一 Bug 修复超 5 轮自动升级人工；单任务连续失败 ≥3 次转人工 |
| A7 | 敏感代码人审 | 红线文件（附录 E）一律人工 Review，禁止自动合并 |

> **模块计数口径**：**15 个单体模块** = 元枢 4（platform / data / semantic / agent-factory）+ 灵犀 11；
> 另有 2 个独立部署进程（`yuanshu-agent-runtime` / `yuanshu-data-jobs`，归元枢，**不计入单体**）、
> 5 个元枢底座 Starter（`yuanshu-starters`）、1 个 BOM；两级聚合 POM（`yuanshu-parent` / `lingxi-parent`）。
> **groupId 统一保留 `com.lingxi`**（组织级版本源不动），仅 Java 包按产品分叉。

**迁移脚本归属与宿主规则**【强制】：

| 规则 | 说明 |
|---|---|
| **迁移宿主唯一** | 全部 Flyway 迁移脚本**统一放在 `yuanshu-platform/src/main/resources/db/migration/{域}/`**，由主应用 `yuanshu-platform` 执行。**业务模块内不得另建 `db/migration/`** |
| **理由** | Flyway 依赖 **classpath 可见性**：脚本放在无启动进程依赖的模块内，将静默不被执行 —— 表不会建、RLS 不生效，且不报错 |
| **依赖方向不因此污染** | 迁移是**部署期关注点**而非业务依赖，收敛到 `yuanshu-platform` 不构成「元枢反向依赖灵犀业务模块」，故不违反 §4 三产品方向约束 |
| **版本号全局唯一** | `V{yyyyMMddHHmm}__{域}_{描述}.sql`；**同一版本号不得出现在两个脚本**（否则 `validate-on-migrate: true` 启动即抛 `Found more than one migration`）。新增脚本前须核对全局唯一 |
| **执行序依赖** | `sys_current_tenant()` 等跨域函数定义在 `sys` 域基线（版本号最小），各域 RLS 策略依赖它 —— 故 `sys` 脚本版本号必须**小于**引用它的所有域脚本 |
| **CI 门禁** | `qa-gate.sh` 须校验：① 版本号全局无重复 ② 各域脚本均位于 `yuanshu-platform` 下（历史缺陷：脚本散落 4 模块，`dt`/`ag`/`mkg` 三域从未被任何进程执行） |
| **真库演练不可省** | 迁移「脚本已编写」≠「已执行」。租户隔离第③道防线（RLS）以真库中`pg_policies` 实际存在为准，验收须直连 DB 核对策略条数 |

> **历史教训（2026-10-16 修复）**：此前 `dt` / `ag` / `mkg` 三域脚本分置于
> `yuanshu-data` / `lingxi-agent` / `lingxi-marketing`，而主应用不依赖这三者，
> 导致 **14 张 `dt_*` + 10 张 `ag_*` 表在任何环境都未被创建**，RLS 防线实际从未生效。
> 静态核对无法发现此类问题 —— 迁移类改动必须做真库演练。

**模块内强制分层**：

```
lingxi-customer/
├── api/          # 对外契约：DTO + 模块接口 + 事件定义（其他模块只允许依赖此包）
├── app/          # 应用层：Controller、应用服务（用例编排）、事务边界、装配
├── domain/       # 领域层：实体、值对象、领域服务、仓储接口（不依赖框架）
├── infra/        # 基础设施：仓储实现、外部适配器（连接器 / MCP 工具 / 数据源）
└── starter/      # 模块自动配置装配
```

| 规则 | 等级 |
|---|---|
| 依赖只能单向：`app → domain ← infra` | 【强制】 |
| 跨模块只能依赖目标模块的 `api` 包 | 【强制】 |
| **跨产品：集群只依赖元枢 `api` 包；元枢禁止依赖灵犀业务域** | 【强制】 |
| **跨产品豁免**：集群可直接依赖 `com.yuanshu.starter.*`（进程内技术件），但业务契约仍必须走 `api` 包 | 【强制】 |
| `domain` 层禁止依赖 Spring / MyBatis / HTTP 等框架 | 【强制】 |
| `api` 包只放 DTO / 接口 / 事件，禁止放实现 | 【强制】 |
| 由 **ArchUnit** 在 CI 强制校验以上六条（含两条跨产品方向规则） | 【强制】 |

### 2.3 前端工程结构（两个独立 app）

```

│   └── yuanshu-console/           # 元枢管理台 @yuanshu/console（治理 / IAM / 提示词 / 指标 / 总览）
│       └── src/ …                 # 结构同上，分区按元枢治理面
├── packages/                      # 5 个内部包（**两 app 共用**）
│   ├── lingxi-ui/                 # 业务组件库（基于 AntD 5 封装）

└── vite.config.ts
```

| 规则 | 等级 |
|---|---|
| **两个 app 各自构建部署**（根 `pnpm build` = `pnpm -r build`），**不做微前端 / 不做 SSR / 不做多框架共存** | 【强制】 |
| **界面归属**：元枢管理台界面（治理 / IAM / 提示词）一律归 `yuanshu-console`，**不在灵犀工作台重复建**（硬约束 1） | 【强制】 |
| 内部包引用一律 `workspace:*` | 【强制】 |
| 每个路由分区登记 `module.config.ts`（路由前缀 / 菜单树 / 权限码 / 功能开关） | 【强制】 |
| 新增模块 = 新增路由分区 + 注册 manifest + 登记权限资源，**禁止私挂路由与菜单** | 【强制】 |
| **`packages/*` 命名例外**：五包为两产品共用的前端基础层，沿用 `lingxi-*` 前缀，属命名分叉的既定例外（改名须走 ADR） | 【强制】 |

## 三、全局约束

> 本章是"跨领域硬约束"的集中清单，效力高于具体编码规约。任何与之冲突的实现一律无效。

### 3.1 环境与部署约束

| # | 约束 | 等级 |
|---|---|---|
| E1 | **全链路禁止 Docker / Kubernetes**：部署形态为云主机 + systemd 进程化 + 脚本化发布 | 【强制】 |
| E2 | 数据库与缓存使用**云端服务**，本地经 **SSH 隧道**连接；应用只连本地映射端口（`127.0.0.1:13306` / `127.0.0.1:16379`），云端地址只存在于隧道配置 | 【强制】 |
| E3 | **禁止应用代码自建 SSH 连接**；隧道建立、监测、重连只由环境脚本负责 | 【强制】 |
| E4 | 开发环境隧道仅 **2 条**（PostgreSQL + Valkey）；新增隧道需架构组审批 | 【强制】 |
| E5 | 所有环境操作（启停 / 迁移 / 体检 / 发布 / 回滚）**只能通过 `scripts/` 中的幂等脚本**执行 | 【强制】 |
| E6 | 夜间/无人值守任务开始前必须先执行 `check-env.sh`；**环境不通则不派发任何任务** | 【强制】 |
| E7 | 连接池超时设短（默认 3s）+ 快速失败，避免隧道抖动导致线程耗尽 | 【推荐】 |
| E8 | 数据任务必须用**水位表**记录进度，断连后从水位续跑，不从头开始 | 【强制】 |

## 四、技术规约

### 4.1 后端编码规约

**4.1.1 语言与风格基线**

【强制】以《阿里巴巴 Java 开发手册（泰山版）》为基线，补充：

- JDK 25 LTS；`record` 用于不可变 DTO；`switch` 模式匹配用于复杂分支；虚拟线程用于 I/O 密集型调用
- 一个方法 ≤80 行；一个类 ≤800 行；超过即拆分
- 禁止魔法值，必须提取常量；常量类按模块内聚（如 `CusConstants`）
- 禁止在 `domain` 层出现框架注解与依赖

**4.1.2 分层职责**

| 层 | 职责 | 禁止 |
|---|---|---|
| Controller | 参数校验 · 权限注解 · 响应包装 | 写业务逻辑 · 直接调 Mapper |
| Application Service | 用例编排 · 事务边界 · 状态机推进 · 事件发布 | 写 SQL · 拼装前端展示逻辑 |
| Domain | 领域模型 · 业务规则 · 不变式校验 | 依赖框架 · 直接访问数据库 |
| Repository/Infra | 数据访问 · 外部适配 | 写业务判断 |

**4.1.3 统一响应体与异常**

【强制】所有 REST 接口返回统一响应体（由 `yuanshu-starter-core` 提供，禁止自行定义）：

```json
{
  "code": 0,
  "message": "success",
  "messageKey": "common.success",
  "data": {},
  "traceId": "a1b2c3d4e5f6"
}
```

- `code`：0=成功，非 0 见附录 A；`message`：面向开发者的英文描述；`messageKey`：面向用户提示的 i18n 键
- 业务异常一律抛 `BizException(ErrorCode)`，由全局异常处理器统一转响应体
- **禁止**在 Controller 捕获异常后自行拼 JSON；**禁止**空 catch 吞异常
- 参数校验用 Jakarta Validation 注解（`@NotNull/@Size/@Pattern`），DTO 声明 + Controller 加 `@Validated`

**4.1.4 事务与一致性**

【强制】

- 事务边界只在 app 层（`@Transactional` 只出现于 app 层）
- **事务内禁止**调用外部 HTTP、发送 MQ、调用 LLM；跨模块通知一律走 Outbox（同一事务写 Outbox 表，提交后投递）
- 聚合根状态流转用领域方法表达（如 `opportunity.advanceTo(stage)`），禁止 Service 直接 set 字段
- 乐观锁用 `version` 字段；冲突时返回 `010006` 并提示用户刷新确认
- 禁止 Seata 强一致方案；一致性用"Outbox + 幂等消费 + 对账任务"

**4.1.5 并发与异步**

【强制】

- 线程池统一通过 `ThreadPoolManager` 创建（线程名 `lx-{域}-{用途}-`）；禁止 `new Thread` 与 `Executors.newXxx` 默认工厂
- I/O 密集调用（外部 API、LLM）用虚拟线程，并显式传播租户上下文
- 分布式锁用统一封装的 `@DistributedLock(key, waitTime)`，锁粒度到业务资源（`lx:lock:{域}:{tenantId}:{资源Id}`），必须有超时
- 定时任务用 `Scheduling + ShedLock`（保证单实例执行）；禁止应用内 `@Scheduled` 直连生产（dev 例外）
- 跨线程传递 `tenantId / userId / traceId` 必须显式传播，禁止依赖 ThreadLocal 隐式继承

**4.1.6 枚举与状态机**

【强制】

- 所有业务状态（线索 / 商机 / 订单 / OTD 节点 / 工单 / 内容 / 任务）定义为枚举并集中管理
- 状态流转表（from → to）显式声明，非法流转抛异常
- 状态流转统一用 Spring StateMachine 定义，规则配置化；**禁止在业务代码散落 `if (status == ...)`**
- 状态变更同时发出领域事件

**4.1.7 审计与来源标记**

【强制】

- 写操作加 `@AuditLog`，记录谁/何时/何地/对什么/做了什么/改前改后值
- 业务表统一记录 `source_type`（HUMAN / AGENT / SYSTEM）+ `source_ref`
- 智能体写入额外记录 `source_agent_code` + `source_task_id`

### 4.2 前端编码规约

**4.2.1 技术栈与工程**

【强制】前端技术栈（版本由 BOM/`package.json` 统一锁定，不跟随 latest）：

| 层面 | 选型 | 约束 |
|---|---|---|
| 框架 | React 19 | 函数组件 + Hooks |

**4.2.2 路由与模块 manifest**

【强制】

- 路由分区与 11 菜单对应：`/workbench` `/customer` `/product` `/order` `/service` `/marketing` `/intel` `/analytics` `/agent` `/knowledge` `/config`
- 每个分区有独立 layout（页面骨架、面包屑、分区权限守卫），共享根 layout（全局导航、主题、Provider）
- 每个分区维护 `module.config.ts`：登记路由前缀、菜单树（titleKey / path / permCode）、分区权限码、功能开关码；菜单与权限码由配置中心下发，前端按权限码过滤渲染
- 功能开关：关闭的分区返回 404 或"功能未开通"页面（开关配置统一管理）
- 跨分区跳转携带上下文用 URL query param：`/customer/detail?id={id}&from=workbench`；**禁止**用全局变量 / localStorage / Context 传业务对象

**4.2.3 组件与状态**

【强制】

- 页面目录结构：`page.tsx`（页面）· `components/`（页面私有组件）· `hooks/`（页面私有逻辑）
- 可复用组件进 `packages/lingxi-ui/`，统一输出：`LxTable`（**全站列表页强制使用**）· `LxForm` · `LxChart` · `LxPermission` · `LxDrawer` · `LxDialog` · `LxAgentSourceTag`（AI 产出标记）· `LxTakeoverButton`（接管）· `LxCurrencyInput` / `LxPhoneInput`（国际化输入）
- 权限控制：`<LxPermission code="cus:lead:assign">` 包裹（**无权限不渲染**，而非禁用后报错），或 `usePermission()` hook
- 类型来源：接口类型由 `lingxi-types` 从 OpenAPI 自动生成，**禁止手写 interface 代替**
- 错误与重试：统一由 `lingxi-request` 处理（错误 Toast、重试策略、响应体解包、401 跳登录）

**4.2.4 配置驱动工作台与统一详情页**

【强制】

- 工作台不得硬编码为固定页面：采用 **widget 注册表 + 布局配置**；widget 必须声明 `key / title / dataSource / component / defaultSpan / drilldown / compareWindow / permission`
- 布局配置按角色下默认模板，支持租户级与用户级覆盖
- 客户 / 商品 / 订单 / 服务四类对象详情页必须使用统一骨架 `ObjectDetailPage`（左信息栏 + 右 Tab：概览/明细/关联/分析），禁止各写一套版式
- 对象详情页保留"智能体建议卡"槽位：有产出时置顶，无产出不占位

**4.2.5 样式与设计令牌**

【强制】

- 设计令牌以 **CSS 变量 + AntD ConfigProvider theme token 双轨**落地，与设计规范一一对应
- 禁止在组件内写死颜色/字号/圆角魔法值；禁止内联 style 写布局
- 禁止直接复用高保真原型的内联样式：**原型是交互与视觉契约，不是代码资产**

### 4.3 接口设计规约

**4.3.1 RESTful 规范**

【强制】URL 规范：

```
/{域}/{资源复数}                  资源集合
  POST   /api/v1/cus/leads                    创建
  GET    /api/v1/cus/leads                    分页（?pageNo=1&pageSize=20&keyword=）
  GET    /api/v1/cus/leads/{id}               详情
  PUT    /api/v1/cus/leads/{id}               全量更新
  PATCH  /api/v1/cus/leads/{id}               局部更新（推荐用于状态类字段）
  POST   /api/v1/cus/leads/{id}/assignment    动作类：动词子资源
  DELETE /api/v1/cus/leads/{id}               逻辑删除
```

- 统一前缀 `/api/v1`；版本升级升路径版本（`/api/v2`），禁止 header 版本号
- 资源名 kebab-case 复数；动作类用 `POST /{资源}/{id}/{动词名词}`（`/emails/{id}/send`）
- 分页参数 `pageNo`（从 1 起）/ `pageSize`（默认 20，最大 200）；分页响应 `{ list, total, pageNo, pageSize }`
- 时间参数一律 UTC ISO8601（`2026-09-11T08:30:00Z`）；金额一律最小货币单位整型或字符串
- 排序/筛选参数统一：`sortBy` + `sortOrder(asc|desc)`、`filter.{字段}`

**4.3.2 契约管理**

【强制】

- API-First：先提交并评审 OpenAPI 3.0 契约（`docs/03-api/{域}/{接口}.yaml`），再开发
- 跨模块调用签名必须与契约一致；CI 用 Pact 做双向契约测试
- 契约变更必须评审 + 在 CHANGELOG 注明兼容性影响
- 前端类型由契约自动生成，禁止手写

**4.3.3 幂等、限流与多租户头**

【强制】

- 所有写操作支持 `X-Idempotency-Key`（UUID），服务端按 key + 租户去重，有效期 24 小时
- 网关限流：租户级 + 接口级；响应头回传 `X-RateLimit-*`
- 多租户上下文只从 `X-Tenant-Id`（网关校验后注入）读取，**禁止业务代码从请求参数取租户**
- 服务间与智能体调用必须透传 `X-Tenant-Id` / `X-Trace-Id` / 用户身份；缺失租户上下文的请求由拦截器直接拒绝

### 4.4 数据库规约

**4.4.1 命名与基础规范**

【强制】

- 表名 `{域}_{实体}` 小写下划线：`cus_lead` · `ord_order` · `dt_entity_company` · `sys_user`；平台表前缀 `sys_`
- 字段名小写下划线；禁用数据库保留字；布尔语义用 `is_` 前缀，类型 `BOOLEAN` 或 `SMALLINT`
- 每表必备审计字段（自动填充，禁止手工赋值）：

```sql
id            BIGINT       -- 雪花ID主键
tenant_id     BIGINT       -- 租户ID（白名单表除外）
created_by / created_at    -- 创建人/时间（UTC）
updated_by / updated_at    -- 更新人/时间（UTC）
is_deleted    SMALLINT     -- 逻辑删除，默认0
version       INT          -- 乐观锁，默认0
```

- 来源标记字段（有智能体写入的表必须有）：`source_type`（HUMAN/AGENT/SYSTEM）· `source_ref` · `source_agent_code` · `source_task_id`
- 业务编码作为唯一业务键列 `biz_code`，唯一索引 `(tenant_id, biz_code)`
- 多语言字段统一 `JSONB`，查询用 `->>'{locale}'`，按需建表达式索引

**4.4.2 索引与查询**

【强制】

- 唯一索引必须带 `tenant_id` 前缀；高频查询组合建联合索引，区分度高的列在前
- 单表索引 ≤5 个；禁止在低区分度列（如 status）单独建索引
- 禁止 `SELECT *`；大字段（TEXT / 大 JSONB）拆附表
- 禁止跨页深翻（`LIMIT 20 OFFSET 100000`），用游标（`WHERE id > {lastId} ORDER BY id LIMIT 20`）
- 【推荐】单表预估超 2000 万行或写入超 5000 行/分钟时，设计期即规划归档或分区（行为类表按月分区）

**4.4.3 变更管理**

【强制】

- 所有 DDL 走 Flyway（PostgreSQL 方言）：`V{yyyyMMddHHmm}__{域}_{描述}.sql`
- 合并主干后**禁止修改已发布脚本**，修正用新脚本
- 前向兼容三原则：只增列不删列 · 不修改列语义 · 删列/表需两个版本周期（先标废弃 → 下版本物理清理）
- 大表变更（>500 万行）必须有变更评审（锁表影响评估）；加列带默认值用惰性求值写法；重建索引用 `pg_repack`，禁止高峰期 `VACUUM FULL`
- 变更脚本与代码同 PR，评审含 DDL 影响评估与回滚预案

**4.4.4 多数据存储使用边界**

| 存储 | 允许承载 | 禁止承载 |
|---|---|---|
| PostgreSQL | 业务事实 · 主数据 · 配置 · 指标体系 · 实体中心 | 日志 · 冷归档大对象 |
| Valkey | 缓存 · 会话 · 计数 · 锁 · 限流 · 事件流 | 需要持久化的业务数据（**任何"缓存里存了就没有 PG 备份"的数据**） |
| 对象存储 | 文件与素材二进制 | 结构化业务数据 |
| OpenSearch（规模化后） | 检索索引（可从 PG/事件重建） | 唯一权威数据源 |
| ClickHouse（规模化后） | 行为明细 · 分析宽表 · 聚合结果 | 在线事务 · 高频点查 |
| pgvector | 向量（知识 / 话术 / 画像 embedding） | 原文存储（原文在 PG 或对象存储） |

【强制】缓存键规约 `lx:{域}:{业务}:{tenantId}:{标识}`；必须设置过期时间（默认 ≤24h）或配套事件驱动失效策略。

**4.4.5 PostgreSQL 特有能力使用约定**

| 能力 | 使用场景 | 约定 |
|---|---|---|
| **RLS（行级安全）** | 多租户兜底防线 | 所有租户表必须启用策略；策略以 `tenant_id = current_setting('app.tenant_id')::bigint` 判定；应用启动时检查策略存在性 |
| **JSONB** | 多语言字段 · 扩展属性 · 来源快照 | 需查询的字段建表达式索引；禁止把核心业务字段塞进 JSONB |
| **pg_trgm** | 客户/企业查重 · 模糊搜索 · 实体消歧 | 名称规范化结果落列 + GIN 索引；相似度阈值 0.85 |
| **pgvector** | 知识 / 话术 / 客户画像向量 | HNSW 索引；检索必须带 `tenant_id` 过滤 |
| **分区表** | 审计日志 · 行为流水 · 线索行为 | 按月分区；分区创建由定时任务提前 2 个月生成 |
| **物化视图** | 看板 · 360 视图 · 指标汇总 | 命名 `mv_{域}_{用途}`；刷新策略显式声明（定时 / 事件触发）；**必须可从事实表重建** |

### 4.5 元枢数智底座规约（L1 大数据 + 语义 + 工厂 · 归属 `yuanshu-data` / `yuanshu-semantic` / `yuanshu-agent-factory`）

**4.5.1 数据源接入**

【强制】

- 所有外部数据源必须实现统一适配器接口 `DataSourceAdapter`（`sourceType` / `pull` / `health` / `rateLimit` / `normalize`）
- **新增数据源 = 新增适配器实现 + 注册配置，不得改动同步主流程**
- 每个源必须有：限速策略 · 重试策略 · 增量水位记录 · 健康监控 · 质量标记
- 源注册信息（凭证、频率、字段映射）配置化，凭证走密钥管理

**4.5.2 企业实体消歧与归并**

【强制】

- 归并规则固定为三级：① **域名完全一致** 或 **规范化名称完全一致** → 自动归并；② 国家+城市一致 且 行业一致 且 名称相似度 **≥0.85** → 人工确认队列；③ 无匹配 → 建新实体（低置信度）
- 归并**必须可逆**：不得物理删除，用 `is_merged` + `merged_into_id`，拆分即回滚映射
- 人工确认 / 拒绝结果必须**回写规则库**（后缀词典 / 别名表）
- 名称规范化必须走统一函数 + 可配置多语言法律后缀词典，禁止各模块自写清洗逻辑
- 实体 360 视图通过视图/物化视图聚合，禁止在业务查询里拼多表 JOIN

**4.5.3 指标体系**

【强制】

- 所有指标必须在 `metric_definition` 注册（`metric_code` / 公式类型 / `sql_template` / 可用维度 / 可用筛选 / 单位 / 精度 / 责任人 / 版本）
- 全系统统一口径，**禁止在业务代码或 SQL 里硬编码指标计算逻辑**
- 指标变更必须版本化并留变更记录；口径争议由数据 Owner 裁决
- 问答式取数只允许使用注册的指标与维度，超范围一律拒绝

**4.5.4 数据质量**

【强制】

- 质量规则覆盖五类：完整性 · 唯一性 · 及时性 · 一致性 · 有效性
- 规则必须配置化（禁止硬编码检查逻辑）；阈值与告警级别可配
- 一致性问题必须走**每日对账任务**（如订单金额 vs 汇总表）
- 输出必须含：质量看板（租户级）+ 问题清单（可下钻）+ 补录入口（一键跳转，不报错）

**4.5.5 即时沉淀（DT-07）**

【强制】

- 业务写入与 Outbox 记录必须**同一事务**（禁止先提交业务再发消息）
- Outbox 投递用定时轮询 + ShedLock 单实例；消费者必须幂等（按 `eventId` 去重）
- 消费者变更不得影响业务表事实源；派生数据必须可重建
- 智能体写入同样经统一 Service → 同一 Outbox 路径

### 4.6 智能体与 AI 开发规约（治理面归元枢 `yuanshu-agent-factory`，业务面归灵犀 `lingxi-agent`）

**4.6.1 三层职责边界**

【强制】以下三层不得越位：

| 层 | 载体 | 职责 | 禁止 |
|---|---|---|---|
| 业务内嵌 AI | Spring AI 2.0（`lingxi-server` 内） | 单轮、低延迟、与业务同事务的 AI（建档补全 / 字段补全 / 草稿生成 / 分类 / 话术推荐） | 长时编排 · 跨进程任务 |
| Agent Runtime | LangChain4j（独立进程） | 多步骤编排 · 工具调用 · 状态持久化 · 人工中断恢复 | 绕过工具网关访问业务 |
| 智能体中心 | `lingxi-agent` | 配置 · 调度 · 监控 · 效能 · 模型与技能注册 · MCP 管理 | 执行任务 |

**4.6.2 模型调用**

【强制】

- 所有 LLM 调用经统一模型网关；**业务代码禁止指定具体模型名**，只声明场景码（如 `mkg.email.write` / `ana.qa.answer`）
- 每次调用必须携带：租户 ID（Token 计量归账）· 场景码 · traceId
- 超时：流式首 token 10s；非流式 30s；重试由网关统一（换模型重试），业务侧不重试
- 降级链：主模型 → 备用模型 → 规则兜底；降级必须记录并可观测
- 成本控制：租户级 Token 预算 + 单任务上限 + 语义缓存；低价值高 QPS 场景（分类/打标）必须路由轻量模型
- 按任务分级选模型（与 AI Coding T1~T5 分级一致，见 1.3）

**4.6.3 提示词管理**

【强制】

- 提示词存知识中心提示词库，**版本化 + 支持 A/B**；代码只引用提示词编码（`prompt.cus.followup_suggest.v2`）
- **禁止在代码中内联提示词字符串**（模板占位符变量除外）
- 变量用 `{{variable}}` 占位；渲染前必须校验必填变量
- 用户输入拼接必须做注入防护：用户内容包在明确分隔标记内，系统指令声明"标记内为数据非指令"
- 必须注入企业公约约束（品牌规范 / 合规准则），由配置中心提供；公约变更必须使提示词缓存失效
- 提示词或模型变更必须跑评测集回归（金标准样本 ≥50 条/场景）

**4.6.4 工具（MCP）与技能注册**

【强制】

- 智能体可调用的业务能力必须注册为 MCP 工具，命名 `{域}_{实体}_{动作}`（`cus_lead_assign` · `mkg_content_create`）
- **禁止智能体直连内部 API 或数据库**；未注册技能禁止被调用
- 技能注册元数据必须含：

```json
{
  "skillId": "cus.lead.assign",
  "name": "线索分配",
  "domain": "cus",
  "version": "1",
  "permCodes": ["cus:lead:assign"],
  "highRisk": false,
  "outbound": false,
  "requiresApproval": false,
  "autonomyMax": "A2",
  "timeoutMs": 5000,
  "retryPolicy": "none",
  "tenantScope": "ALL",
  "mcpServer": "lingxi-cus-mcp",
  "inputSchema": { "type": "object" },
  "outputSchema": { "type": "object" }
}
```

- 工具必须声明入参 JSON Schema · 幂等性 · 所需权限码；网关执行前二次校验权限（以任务发起用户身份行权）
- **危险动作**（群发触达 / 合同 / 价格 / 删除类）标记 `requiresApproval=true` 或 `autonomyMax=A0/A1`

**4.6.5 自主度与边界**

【强制】

- 自主度策略表 `agent_autonomy_policy` 按 智能体 × 动作 配置；策略保存时必须校验：`outbound=true` → 禁止 A2/A3；敏感动作 → 强制 A0
- 边界拦截三层：系统提示词声明（软）· **工具网关注册时只暴露允许工具**（硬）· 动作分类与风险规则校验（兜底）
- 拦截后必须：状态置 `NEEDS_HUMAN` + 生成人工待办 + 界面高亮 + 记录拦截原因
- 每个智能体必须实现 `AgentBoundaryRule` 声明其"不做清单"，未声明边界规则的智能体不允许上线
- 默认从严：新增智能体 / 新增动作默认 A0

**4.6.6 人机协同与产出治理**

【强制】

- 智能体产出必须经统一 Service 入库，并标记来源（`source_type=AGENT` + agent_code + task_id）
- 任务状态必须持久化（含上下文快照与检查点），保证任意步骤可接管、可恢复、可终止
- 人工接管后必须能中断/取消在途自动动作；人工修改 AI 产出必须保留变更痕迹
- 冲突处理用乐观锁，冲突时提示"该记录刚被智能体更新，请确认"
- 每个智能体任务必须记录完整轨迹（输入 / 规划 / 工具调用与结果 / Token / 输出），供监控与效能评估

**4.6.7 RAG 与内容安全**

【强制】

- RAG 检索必须带 `tenant_id` + 知识权限过滤；引用来源（知识条目 ID）必须随结果返回，前端可展示"依据"
- 问答式取数只生成受限查询计划（指标/维度/筛选 DSL），白名单校验后翻译执行；**禁止 LLM 直接生成并执行 SQL**
- 提示词组装前 PII 脱敏；敏感字段禁止送入外部模型
- AI 生成内容对外发送前必须过内容安全检测（敏感词 + 合规），命中即阻断并记录
- 输出必须做结构化 Schema 校验，不合规拒绝执行

### 4.7 集成与事件规约

**4.7.1 通信方式选择**

【强制】跨模块通信只允许三种方式，按序选择：

| 场景 | 方式 | 示例 |
|---|---|---|
| 需要实时结果的读 / 简单写 | **同步 API**（进程内 Interface，走 `api` 包契约） | 订单模块读客户主数据 |
| 业务状态流转通知、可异步处理 | **领域事件**（Outbox → Valkey Stream） | 线索创建 → 通知 → 分配 |
| 批量数据同步、分析管道 | **数据任务**（定时 / CDC） | 行为数据入分析汇总 |

【强制】禁止：跨模块直连他人数据库/Mapper · 跨模块循环依赖 · 同步链路 >3 跳 · 前端串多个写接口充当跨域事务。

**4.7.2 领域事件规约**

【强制】事件主题命名 `lx.{域}.{实体}.{动作}`（`lx.cus.lead.created` · `lx.ord.otd.delayed` · `lx.ag.task.completed`）。

【强制】事件体统一信封：

```json
{
  "eventId": "uuid",
  "eventVersion": 1,
  "occurredAt": "2026-09-11T08:30:00Z",
  "tenantId": 10086,
  "actorType": "AGENT",
  "actorId": "agent-cus-01",
  "payload": {},
  "traceId": "..."
}
```

- 消费者必须幂等（按 `eventId` 去重表）；消费失败进重试（16 次后进死信 `lx.dlq.{原主题}` 并告警）
- 事件 Schema 向后兼容（只加字段）；破坏性变更升 `eventVersion` 并双写一个迁移周期
- 事件只放必要字段 + 实体 ID，禁止塞大对象

**4.7.3 主数据引用**

【强制】

- 跨模块引用主数据（客户/商品/联系人/员工）只存 `ID + 冗余展示快照`；快照仅用于列表展示，业务判断必须回源取实时值
- 主数据变更（客户合并、员工离职）由权威源发事件，引用方订阅更新快照
- 主数据权威源唯一：客户/企业实体归 L1 数据底座与客户中心，商品归商品中心，员工归平台

**4.7.4 连接器规约**

【强制】

- 外部能力（邮件 / WhatsApp / 社媒 / 访客识别 / 客服渠道 / 支付 / 数据商）统一抽象为连接器接口：`send` / `onInbound` / `accountHealth` / `rateLimit` / `verifySignature` / `quota`
- **禁止业务代码中硬编码厂商 SDK 散落调用**；更换服务商只替换连接器实现，业务代码零改动
- 账号资产归 L1 数据底座管理，连接器只引用资产 ID；凭证加密托管、永不出网关
- 外部调用必须熔断 + 舱壁隔离（独立线程池/信号量）
- 入站回调统一验签（HMAC）+ 时间戳防重放 + 幂等去重（Webhook 会重投）
- 营销触达必须内置频控与退订（unsubscribe）机制，退订名单全局生效——**合规是产品底线**
- 客服多渠道统一会话模型（渠道 / 会话 ID / 客户 ID / 坐席或 AI 主体），AI 转人工必须保留上下文

### 4.9 安全规约

**4.9.1 认证与会话**

【强制】

- 统一认证基于 **Keycloak**（OIDC / OAuth2.1）：JWT RS256 签名 + JWKS 轮换
- Access Token 15 分钟 + Refresh Token 轮换（Rotation）+ 吊销黑名单（Valkey）
- JWT 只放摘要（user_id / tenant_id / roles）；**完整权限实时走 Casbin 决策**，不放进 Token
- SPA 用 Authorization Code + PKCE；服务间用 Client Credentials；智能体用独立 client + 严格 scope
- **禁止**业务服务自建用户名密码表分叉登录
- 密码策略由 Keycloak 强约束；登录失败锁定（5 次锁 15 分钟）；敏感操作二次验证

**4.9.2 授权**

【强制】

- 三层权限（功能 / 行级 / 字段）统一由平台 Casbin 模型集中管理，业务模块经 SDK 调用，**禁止各模块私有 ACL 表另搞一套**
- 权限决策集中在平台服务，业务代码禁止自研判断逻辑
- 字段权限通过序列化层动态脱敏（注解 + 拦截器）实现；成本价 / 利润率默认隐藏

**4.9.3 数据安全**

【强制】

- 数据分级：L1 公开 / L2 内部 / L3 敏感（客户联系方式、沟通记录）/ L4 高敏（凭证、密钥）
- L3 及以上：展示脱敏（邮箱/手机掩码 + 字段权限）· 导出审批 + 水印 · 强制审计
- 传输全程 TLS 1.2+；L4 存储加密（KMS/OpenBao 信封加密）；敏感字段用 pgcrypto
- 日志与消息中禁止出现明文凭证与完整敏感字段
- **租户数据越权为 P0 级安全事故**：每个对外 API 必须含跨租户访问测试用例（租户 A 的 token 访问租户 B 资源必须 403/404）

**4.9.4 租户隔离四道防线（缺一不可）**

【强制】

```
① 应用层拦截器自动注入 tenant_id（全局表白名单制）
② 数据权限过滤（行级 scope + 字段权限）
③ PostgreSQL RLS 兜底（绕过应用层也拦得住）
④ 隔离测试用例（新增带租户数据的接口必须提交，缺失则 CI 失败）
```

隔离测试套件 6 项：数据层越权 · 列表层归属 · 检索层（含向量）· 智能体层 · 导出对账 · RLS 直连校验。

**4.9.5 通道与外部集成安全**

【强制】

- 社媒/邮件/WhatsApp 凭证由数据底座统一加密托管，业务侧经授权代理使用，凭证永不出网关
- 所有出站 Webhook / 回调 URL 登记白名单；入站回调统一验签（HMAC）+ 时间戳防重放
- 营销触达必须内置频控与退订机制，退订名单全局生效
- 支付：商户密钥只存密钥管理，配置项由配置中心维护，**禁止前端直持商户密钥**

**4.9.6 安全门禁**

【强制】门禁阈值：

| 阶段 | 门禁 | 阈值 |
|---|---|---|
| 提交前 | Semgrep + SpotBugs + ESLint + 单测 | 0 高危 |
| PR | Dependency-Check + gitleaks + 硬编码扫描 | 0 高危 CVE · 0 密钥泄露 · 0 硬编码命中 |
| 合并前 | Pact 契约 + 覆盖率 | 覆盖 ≥70%（新增 ≥80%） |
| 合并后 | 集成测试 + 租户隔离套件 | 全绿 |
| 发布前 | OWASP ZAP DAST | 0 高危 |
| 交付前 | 全量安全审计 + 第三方渗透 | 达商业化门禁清单 |

### 4.10 国际化规约

【强制】

- **时间**：数据库与 API 一律 UTC；服务端按"用户时区"或"客户时区"格式化；客户相关时间轴按客户时区展示并标注时区
- **语言**：前后端所有面向用户的文案走 i18n（前端 react-i18next，后端 `messageKey`）；**禁止硬编码中文文案**（注释除外）
- 语言包 key 规范：`{域}.{模块}.{位置}.{含义}`，如 `cus.lead.list.title`；按域分区管理语言包文件
- **币种金额**：存"金额（最小单位整数）+ 币种 ISO4217 + 汇率快照"；报表换算用快照汇率；禁止 float 运算
- **字符集**：全链路 UTF-8；姓名/公司名排序按目标语言排序规则（ICU COLLATION，如 `collate "zh-x-icu"`）
- 【推荐】新功能开发即产出中英双语语言包；AI 辅助翻译生成草稿 + 人工校对后入库

### 4.11 可观测规约

**4.11.1 日志**

【强制】

- 统一 JSON 结构化日志，必带字段：`timestamp(UTC)` · `level` · `service` · `traceId` · `tenantId` · `userId`
- 级别使用：ERROR（需人处理）· WARN（自动恢复但需关注）· INFO（关键业务动作）· DEBUG（仅 dev）；**生产禁止 DEBUG**
- 脱敏：手机号 / 邮箱 / 凭证 / Token 按规则掩码；禁止打印完整请求体（只打摘要与 ID）
- 业务关键动作统一打点格式：`BIZ|{域}|{动作}|{实体类型}|{实体ID}|{结果}`

**4.11.2 指标与链路**

【强制】

- 每个服务必须暴露：QPS · RT（P50/P95/P99）· 错误率 · JVM 指标（Micrometer → Prometheus）
- Agent Runtime 暴露同等口径指标（任务吞吐 / 失败率 / 接管率 / Token 消耗 / 越界拦截数）
- 连接器与模型网关额外暴露：送达率 · 打开率 · 失败率 · 各场景调用量与成功率 · 成本
- **一条 Trace 贯穿全链路**：前端请求 → 网关 → 业务模块 → Outbox → 智能体运行时 → 工具调用 → 外部 API/LLM
- traceId 透传路径：HTTP header（`X-Trace-Id`）→ 事件信封 → LLM 调用 → 工具调用
- OpenTelemetry 语义约定统一由 `yuanshu-starter-observability` 提供，禁止各模块自定义 span 命名

**4.11.3 告警分级**

【强制】

| 级别 | 场景 | 响应 |
|---|---|---|
| P0 | 服务不可用 · 数据越权 · 通道中断 · 租户隔离异常 | 立即通知，5 分钟响应 |
| P1 | 错误率 >1% · 队列/Outbox 积压 · 智能体失败率异常 | 15~30 分钟响应 |
| P2 | 慢查询 · 磁盘水位 · 成本异常 · 数据质量 | 当日处理 |

### 4.12 测试规约

| 层级 | 要求 | 等级 |
|---|---|---|
| 单元测试 | 领域层核心逻辑（状态机 / 评分 / 规则）行覆盖率 ≥80%；JUnit 5 + Mockito | 【强制】 |
| 契约测试 | 跨模块 API 与事件必须有 Pact 契约测试，契约变更 CI 双向校验 | 【强制】 |
| 集成测试 | 仓储与外部依赖用 Testcontainers（真实 PostgreSQL / Valkey）；智能体编排用本地测试图 + Mock MCP 工具 | 【强制】 |
| API 测试 | 每个对外 API 必须覆盖五类用例：正常 · 参数校验 · 权限（无权限 403）· **跨租户（403）** · 幂等 | 【强制】 |
| 隔离测试 | 6 项隔离套件为**合并前必跑门禁**（见 4.9.4） | 【强制】 |
| E2E 测试 | 核心业务流（线索创建→分配→跟进→商机→成交）用 Playwright 冒烟 | 【推荐】 |
| AI 评测 | 智能体场景建评测集（金标准样本 ≥50 条/场景）；提示词或模型变更跑回归对比 | 【强制】 |
| 性能测试 | 关键接口按《技术架构和组件选型方案2.0》4.8 性能指标执行基准测试；发布前回归 | 【推荐】 |

【强制】CI 流水线顺序：编译 → ArchUnit 依赖检查 → 单测 → 契约测试 → 覆盖率门禁 → 隔离套件 → 静态扫描 → 依赖与密钥扫描。任一环节失败阻断合并。

### 4.13 配置与脚本规约

**4.13.1 配置管理**

【强制】

- 五个配置文件：`config/app.yml` · `db.yml` · `cache.yml` · `model.yml` · `tunnel.yml`（不含真实密钥）
- `.env` 存真实密钥与口令（**必须 gitignore**）；`.env.example` 入库并含全部变量说明
- `model.yml` 是**唯一**允许出现模型名的地方；业务代码只引用场景码
- 配置读取统一走配置服务/配置类，禁止散落 `System.getenv` 与 `@Value` 到处取值
- 配置变更必须留版本与操作人

**4.13.2 脚本清单（全部幂等，Agent 只能通过脚本操作环境）**

| 脚本 | 职责 | 幂等要求 |
|---|---|---|
| `tunnel-up.sh` | 建立 SSH 隧道（autossh + `ServerAliveInterval 30` + `ServerAliveCountMax 3` + `ExitOnForwardFailure yes`） | 重复执行不产生重复进程 |
| `check-tunnel.sh` | 三层探测：TCP 端口 → DB 真查询 → 缓存真 PING；失败自动重建；仍不通则通知并**暂停当晚派发** | 只读探测 |
| `init-db.sh` | 数据库初始化与迁移（经隧道连云端库），含迁移前备份 | 可重复执行 |
| `start-dev.sh` / `stop-dev.sh` | 前后端服务启停（PID 文件管理，端口占用检查） | 重复执行安全 |
| `check-env.sh` | 四层体检：隧道 / DB / 缓存 / 服务健康 | 只读 |
| `qa-gate.sh` | 验收门禁：测试 + 覆盖率 + SAST + 依赖扫描 + 硬编码反模式扫描 | 只读 |
| `dispatch-task.sh` | 读任务清单 → 分级选模型 → 调 AI Coding 工具 | 按任务 ID 去重 |
| `deploy.sh` / `rollback.sh` | 发布与回滚（灰度切换，目标 < 5 分钟） | 版本目录隔离 |

### 4.14 版本管理与发布规约

**4.14.1 Git 规约**

【强制】

- 主干开发 + 短生命周期特性分支：`feature/{域}-{描述}-{任务号}` · `fix/` · `hotfix/`；**分支存活 ≤3 天，diff ≤400 行**
- Commit 格式：`{类型}({域}): {描述} #{任务号}`；类型 `feat / fix / refactor / test / docs / chore`
- 合并需 ≥1 名模块 Owner 评审 + CI 全绿；主干随时可发布
- 迁移脚本与代码同仓库同 PR 提交，评审必须含 DDL 影响评估
- 禁止绕过 hooks（`--no-verify`）、禁止 force push 主干

**4.14.2 版本与发布**

【强制】

- 语义化版本 `MAJOR.MINOR.PATCH`（对外 API 兼容性对齐 MAJOR）；前端统一版本，随服务端主版本节奏发布
- 发布窗口：常规每周两次；通道类服务发布避开营销任务高峰；节日 freeze 期需审批
- 发布 Checklist（缺一不可）：迁移脚本已验证 → staging 回归通过 → 灰度计划（按租户比例）→ 回滚预案 → 观测面板值班确认
- 回滚目标 <5 分钟（保留上一版本产物，脚本一键切换）
- 功能开关：新模块默认关闭，按租户白名单灰度放量；开关与配置登记在配置中心

### 附录 B：HTTP 头约定

【强制】全站统一 HTTP 头（网关、服务间、前端、智能体工具调用同等遵守）：

| Header | 说明 |
|---|---|
| `Authorization` | Bearer Access Token（Keycloak 签发 JWT） |
| `X-Tenant-Id` | 租户 ID（网关校验与 Token 一致后注入；服务内从 TenantContext 读取，**禁止从请求参数取租户**） |
| `X-Trace-Id` | 链路追踪 ID（网关生成，全链路透传：HTTP → 事件 → LLM → 工具） |
| `X-Idempotency-Key` | 写操作幂等键（UUID） |
| `Accept-Language` | 用户语言（locale） |
| `X-Timezone` | 用户时区（IANA 名称，可选，优先用户配置） |
| `X-Agent-Code` | 智能体标识（仅智能体发起调用时携带，用于审计与效能归集） |

【强制】服务间与智能体调用必须透传 `X-Tenant-Id` / `X-Trace-Id` / 用户身份上下文；缺失租户上下文的请求由拦截器直接拒绝。

### 附录 D：硬编码与反模式扫描规则（`qa-gate.sh`）

【强制】每次 diff 扫描以下反模式，命中即验收 FAIL 并生成 FIX 任务：

| # | 扫描目标 | 匹配模式（示例） | 说明 |
|---|---|---|---|
| 1 | 数据库连接串 | `jdbc:(postgresql\|mysql)://` 出现在非 `config/` 文件 | 疑似硬编码连接串 |
| 2 | 云端地址 | 出现非 `127.0.0.1` 的 IP + 端口组合 | 疑似硬编码环境地址 |
| 3 | 密钥与口令 | `(password\|secret\|apikey\|api_key\|token)\s*[:=]\s*["'][^"']{6,}` | 疑似硬编码凭证 |
| 4 | 模型名 | `(gpt-\|qwen\|claude\|gemini\|deepseek)[a-z0-9.\-]*` 出现在非 `config/model.yml` | 模型名禁止出现在代码 |
| 5 | 服务端直连库 | 非 `infra` 层出现 `JdbcTemplate` / `DataSource` / `@Mapper` 引用 | 越层访问数据库 |
| 6 | 跨模块表 JOIN | SQL 出现非本域表前缀（如 `cus_` 模块出现 `ord_order`） | 违反模块边界 |
| 7 | 智能体专用写接口 | 路径含 `/api/v1/agent/**` 且为 POST/PUT/PATCH | 影子 API（违反双通道同源） |
| 8 | 未注册工具调用 | 编排代码出现非 MCP 工具直调（`restTemplate` 直连业务 API） | 智能体必须走工具网关 |

| 10 | 前端硬编码文案 | `.tsx` 中出现中文字符串（非注释 / 非 i18n key） | 违反国际化规约 |
| 11 | 前端手写接口类型 | `lingxi-types` 之外出现与 API 响应同名的 `interface` | 类型必须由 OpenAPI 生成 |
| 12 | 前端直调 HTTP | 组件内出现 `axios.` / `fetch(` | 必须走 `lingxi-request` |

### 附录 E：三条不可自动合并红线

【强制】以下三处 diff 命中即**冻结 PR，禁止自动合并**，必须人工 Review（AI Coding 流水线同步校验）：

| 红线 | 触发路径 / 模式 | 风险性质 |
|---|---|---|
| **① 认证与会话** | `yuanshu-starters/yuanshu-starter-security/**` · `yuanshu-platform/auth/**` · `*SecurityConfig*` · `*TokenService*` · `*LoginController*` | 漏一个校验点即可被绕过登录 |
| **② 租户隔离与权限** | `*TenantInterceptor*` · `*DataScope*` · `*PermissionEvaluator*` · `*Casbin*` · `docs/03-api/**/rls-*.sql` | 漏一个 `where tenant_id` 即跨租户泄露（P0 事故） |
| **③ 计费 / 配额 / 支付** | `billing/**` · `quota/**` · `payment/**` · `*CreditsService*` | 错一次扣减即资损，且不可逆 |

**判定依据**：不是任务难易，而是**错误代价不可逆**——这三类错误普通测试抓不到，却直接构成商业与合规风险。
