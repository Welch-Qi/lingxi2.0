## 一、三条不可自动合并红线

| 红线 | 触发路径（已三产品化） | 为什么不可逆 |
|---|---|---|
| **① 认证与会话** | `yuanshu-starters/yuanshu-starter-security/**` · `yuanshu-platform/auth/**` · `*SecurityConfig*` · `*TokenService*` · `*LoginController*` | 漏一个校验点即可**绕过登录** |
| **② 租户隔离与权限** | `*TenantInterceptor*` · `*DataScope*` · `*PermissionEvaluator*` · `*Casbin*` · `rls-*.sql` | 漏一个 `where tenant_id` 即**跨租户泄露（P0）** |
| **③ 计费 / 配额 / 支付** | `billing/**` · `quota/**` · `payment/**` · `*CreditsService*` | 错一次即**资损**，不可逆 |

> 命中即冻结 PR、禁止自动合并，必须人工 Review。
> 判定依据不是任务难易，而是**错误代价不可逆**。

> **红线① 已收敛（2026-10-13，随 Q2 落地）**：认证/权限实现当前在 `com.yuanshu.starter.security`（Q2 后），红线① 同时列出 `yuanshu-starters/yuanshu-starter-security/**`（现在）与 `yuanshu-platform/auth/**`（后续 IdP/登录/Token 落地处），**覆盖两个阶段**，路径口径与代码现状一致。

## 二、认证

| 项 | 结论 |
|---|---|
| IdP | **Keycloak 26**（OIDC / OAuth2.1）；**Realm 天然对应租户**（`sys_tenant.realm` 字段与 Realm 一一对应，见基线迁移注释） |
| 口令存储 | **元枢数据库不存密码**（`sys_user` 表注释明令：口令与凭证由 Keycloak 管理） |
| 客户端模式 | 前端 Authorization Code + PKCE；服务间 Client Credentials；**智能体独立 client + 严格 scope** |
| Token 策略 | Access 15 分钟 + Refresh 轮换 + 吊销黑名单（Valkey） |
| Token 内容 | **只放摘要**（`user_id` / `tenant_id` / `roles`），完整权限**实时走 Casbin 决策** |
| 登录方式 | 账号密码 + 图形验证码；预留企业微信/钉钉/飞书 SSO（Keycloak IdP 配置即可，不改业务代码） |

## 三、授权：Casbin 三层

| 层 | 模型 | 技术实现 | 归属 |
|---|---|---|---|
| **功能权限** | RBAC（角色-菜单-按钮），权限码 `{域}:{对象}:{动作}` | Casbin policy 表 | 元枢决策 |
| **行级（数据）权限** | `SELF` / `DEPT` / `DEPT_AND_SUB` / `CUSTOM` / `ALL` | MyBatis-Plus 数据权限拦截器 + Casbin 数据策略 | 元枢决策 |
| **字段权限** | 字段级可见 / 可编辑 | 序列化层动态脱敏（注解 + 拦截器）；成本价、利润率默认隐藏 | 元枢决策 |

### 3.1 决策入口（代码实读 `PermissionService`）

```java
enforcer.enforce(String.valueOf(userId), permCode, "access");
```

| 设计 | 说明 |
|---|---|
| **性能** | Enforcer 全量策略**常驻内存**，决策为本地内存计算（微秒级），**无远程调用** |
| **撤权即时生效** | 策略变更经 **Valkey 发布订阅**通知各实例 `reload()` 重载 |
| **决策集中** | 权限判定**只在元枢 platform**，业务模块**禁止自研判断**（规约 §4.8.1） |

### 3.2 数据范围枚举（代码实读 `DataScope`）

`SELF`（仅本人）· `DEPT`（本部门）· `DEPT_AND_SUB`（本部门及下级）· `CUSTOM`（自定义资源集合）· `ALL`（全部）

> ⚠️ **`ALL` 仍受租户隔离约束** —— "全部数据"是租户内全部，不是全平台。平台统一定义该枚举，**各模块不得自定义口径**。

### 3.3 声明式注解（代码实读）

| 注解 | 用途 |
|---|---|
| `@RequirePermission("cus:lead:assign")` | 功能权限校验，由 `RequirePermissionAspect`（`@Aspect` + `@Before`）切面执行 |
| `@RequireDataScope` | 行级数据权限注入 |

> 技术依赖：Spring Boot 4.1 中 AOP starter 坐标为 **`spring-boot-starter-aspectj`**（4.1 已将 `spring-boot-starter-aop` 更名）。

## 四、智能体安全（AI 特有风险）

### 4.1 自主度不可越界

| 规则 | 内容 |
|---|---|
| 对外内容与触达 | **≤ A1（必须人审）** |
| 价格 / 合同 / 赔偿 / 投诉 | **强制 A0**，不可配置为 A2/A3 |
| `is_outbound=true` 的动作 | 策略表**禁止配置为 A2/A3**（配置校验时拒绝保存） |
| 默认从严 | 新增智能体/动作默认 A0，需显式上调并留审批记录 |
| 判据唯一 | `AutonomyPolicyApi#resolve(agentCode, sceneCode)` —— **运行时唯一自主度判据**，业务代码禁止自行判断能否放行 |

### 4.2 三道护栏（代码实读 `GuardrailChain`）

| 道 | 机制 | 现状 |
|---|---|---|
| **输入护栏** | 提示词注入模式检测 + 用户输入与系统指令分隔 + **PII 脱敏**（成本价、联系方式等禁止送入外部模型） | 接口已定义（`sanitizeInput`） |
| **输出护栏** | 结构化 Schema 强校验（不合规拒绝执行）+ 敏感词与合规检测（**对外发送前必检**，命中即阻断并记录） | 接口已定义（`validateOutput`） |
| **越界拦截** | 动作分类与风险规则校验（金额阈值 / 投诉情绪 / 超知识库问题）→ **转人工** | 错误码 `600003` |

> 输出不合规抛 `BizException`：`600003`（越界拦截）/ `010004`（参数非法）。

### 4.3 越权与数据外泄防护

| 风险 | 措施 |
|---|---|
| 越权访问 | 工具网关注入租户与用户上下文；检索层强制 `tenant_id` + 数据权限（**与人工通道同一套**） |
| 数据外泄 | 提示词组装前 PII 脱敏；**禁送成本价/联系方式等敏感字段**；可选私有化模型通道 |
| 边界拦截三层 | ① 提示词层（软约束）② **网关层（硬约束：不做的工具根本不注册给该智能体，模型无法调用）** ③ 规则层（金额阈值/情绪/超知识库） |

### 4.4 场景码约束

业务代码只声明**场景码**，禁止指定模型名（模型名只在 `config/model.yml`）：

`mkg.email.write` · `kc.script.suggest` · `ana.qa.answer` · `cus.lead.score` · `kc.prompt.embed`

理由：模型可随时替换与降级（主 → 备用 → 规则兜底），写死模型名会导致换模型要改业务代码并回归全部场景。

## 五、数据安全

| 项 | 措施 |
|---|---|
| 静态加密 | 敏感字段 **pgcrypto** 加密；数据库与对象存储静态加密 |
| 传输 | TLS 1.2+；备份加密 |
| 日志 | 自动**掩码**手机号 / 邮箱 / 密钥；结构化 JSON + `traceId` |
| 多语言字段 | 统一 JSONB（`sys_user.display_name` 注释为范例） |
| 审计 | 全量操作审计（含智能体），按月分区；关键动作（价格/合同/权限变更/接管）**强制调用 `AuditApi`** |
| 审计字段自动填充 | `AuditMetaObjectHandler`：`id` / `tenant_id` / `created_by` / `created_at` / `updated_by` / `updated_at` / `is_deleted` / `version`，**禁止业务代码手工赋值** |

## 七、**三产品安全职责划分（本次新增重点）**

| 面 | 元枢（底座） | 灵犀（业务） | 开物（一期不实现） |
|---|---|---|---|
| **治理面安全** | ✅ 认证 IdP · Casbin 决策 · 租户隔离 · 审计 · 自主度策略 · 智能体注册准入 · 配额账本 | 继承，不重复实现 | 经 `AgentRegistrationApi` 接入，沿用元枢治理面 |
| **业务面安全** | 提供能力 | ✅ 触达合规（GDPR/PIPL 导出与删除）· 业务字段权限 · 内容合规（敏感词 / 企业公约） | 工业数据边界（待二期明确） |
| **对外内容安全** | 护栏能力（`GuardrailChain`） | ✅ 对外内容**强制人审**（自主度 ≤ A1） | — |

### 关键原则

1. **权限决策只在元枢** —— 灵犀各域禁自研判断（`contracts.md` 与规约 §4.9.2 双口径）。
2. **自主度判据唯一** —— `AutonomyPolicyApi` 是运行时唯一来源，禁止业务代码自行判断放行。
3. **开物接入即受管** —— 五智能体**必须经 `AgentRegistrationApi` 注册**，`OwnerProduct` 区分 LINGXI / KAIWU；未注册即视为越权。
4. **元枢变更须前向兼容**（硬约束 3）—— 底座动一次两集群都要回归，故走版本 + 灰度。

### 机器校验现状（ArchUnit 6 条，随 Q2 同步）

| 规则 | 约束 | 与安全的关系 |
|---|---|---|
| 规则 4（已更名） | **底座 Starter 只承载技术能力，不得反向依赖业务模块** | 原名「跨模块只依赖 api」名实不符，Q2 顺手纠正为实际约束 |
| 规则 5 | `com.yuanshu..` 禁止依赖灵犀 11 个业务域 | 硬约束 1 的机器化（元枢不承载业务） |
| 规则 6 | 灵犀禁止依赖元枢**非 api 包**，**豁免 `com.yuanshu.starter..`** | 硬约束 2 的机器化；豁免项是**刻意的安全边界**：底座 Starter 是进程内技术件（响应体/租户/权限/可观测/模型网关），集群直接依赖它不等于"自建第二套底座"，**业务契约仍必须走 api 包** |

> 验证：`mvn -fae test` → ArchUnit **Tests run 6 / Failures 0 / Errors 0**。

## 八、门禁阈值（引自技术规约 §4.7）

| 阶段 | 门禁 | 阈值 |
|---|---|---|
| 提交前 | Semgrep + SpotBugs + ESLint + JUnit | **0 高危** |
| PR | Dependency-Check + gitleaks | **0 高危 CVE · 0 密钥泄露** |
| 合并前 | Pact 契约 + JaCoCo/Vitest 覆盖率 | 总体 **≥70%**，新增代码 **≥80%** |
| 合并后 | Testcontainers 集成测试 + **租户隔离套件** | **全绿** |
| 发布前 | OWASP ZAP DAST | **0 高危** |
| 交付前 | 全量安全审计 + 第三方渗透 | 商业化门禁清单 |

> ⚠️ **CI 现状缺口（本次核查发现）**：`lingxi-ops/ci/gitlab-ci.yml` 的 16 个 job 中**无 lint / i18n 门禁**（grep `lint|eslint|i18n` 命中 0）。而 `lingxi-web/AGENTS.md` 明确「改过文案后必须跑 `check-i18n.py`（它不在 `pnpm lint` 里）」—— 该门禁目前只靠人工自觉，**建议补 CI job**（属代码改动，另开分支）。
