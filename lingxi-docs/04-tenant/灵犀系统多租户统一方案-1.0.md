## 一、隔离模型

| 项 | 结论 |
|---|---|
| 一期隔离形态 | **共享库 + 共享表 + `tenant_id` 列** |
| 演进 | 二期起为大客户提供独立 Schema（迁移单元清晰） |
| 租户列名 | **统一 `tenant_id`，不允许模块自定义**（`TenantTableWhiteList.tenantColumn` 固定，配置可改但属全局口径） |
| 表策略 | **白名单制**（非黑名单）：**新增表默认必须带租户列** |

> 白名单制是刻意选择：黑名单一旦漏配即跨租户泄露；白名单只有"显式豁免"才免注入，新增表默认安全。
> 仅字典、平台配置等全局共享表可列入白名单，**新增白名单项须架构组评审**。

## 二、四道防线（缺一不可）

| 道 | 机制 | 落点 | 可被机器检出 |
|---|---|---|---|
| **①** | 租户拦截器自动注入 `tenant_id` | MyBatis-Plus 租户插件 + `YuanshuTenantLineHandler` | 白名单配置校验 |
| **②** | 行级数据权限 | `DataScope` 枚举 + MyBatis-Plus 数据权限拦截器 | ArchUnit 分层规则 |
| **③** | **PostgreSQL RLS 兜底** | 基线迁移中的 `CREATE POLICY` | `verify-tenant-isolation.sh` ⑥ |
| **④** | 隔离测试用例 | `verify-tenant-isolation.sh` 六项 | 合并前必跑 |

> **防线的意义**：即使应用层漏写 `where tenant_id`，第 ③ 道 RLS 仍能拦住 —— 这是**兜底而非重复**。
> 因此**任何自定义 SQL 必须手写 `tenant_id` 条件**：RLS 只在会话设置了 `app.tenant_id` 时生效，绕过连接池复用或手工直连都可能让判定函数返回 `NULL` 而放行。

## 三、第①道防线的实现细节（代码实读）

### 3.1 租户上下文 `TenantContext`

```java
public record Principal(Long tenantId, Long userId, String agentCode, String locale)
```

| 设计 | 理由 |
|---|---|
| **缺失即抛异常** | `current()` 在无上下文时抛 `IllegalStateException`，**绝不回退到"全网可见"** |
| **显式传播 `wrap()`** | 虚拟线程与提交到线程池的任务**不会继承 ThreadLocal**，必须用 `wrap()` 显式携带 |
| `agentCode` | 仅智能体发起时非空，用于**审计与效能归集**（`isAgentCall()`） |
| `locale` | 随上下文传播，避免下游重复解析 |

> ⚠️ **开发期最易踩的坑**：异步/虚拟线程场景忘记 `wrap()` → 下游拿不到租户 → 抛异常或（若被误改为 null 兜底）跨租户。**禁止把"缺失即抛"改成"缺失即 null"**。

### 3.2 免注入白名单 `TenantTableWhiteList`

```yaml
yuanshu:
  tenant:
    enabled: true              # 生产环境禁止关闭
    tenant-column: tenant_id   # 统一列名
    white-tables: [sys_dict_type, ...]   # 免注入的全局共享表
```

> `enabled` 是安全开关：**生产关闭等于全库裸奔**，属红线操作。
> 配置前缀已随 Q2 收敛为 `yuanshu.tenant`（原 `lingxi.tenant`）；配置根键 `lingxi:` → `yuanshu:` 已同步 `application.yml` 与 `lingxi-server/config`、`lingxi-ops/config` 各 4 份。

## 四、第③道防线：PostgreSQL RLS（已落地）

### 4.1 判定函数（基线迁移实读）

```sql
CREATE OR REPLACE FUNCTION sys_current_tenant() RETURNS bigint AS $$
   SELECT nullif(current_setting('app.tenant_id', true), '')::bigint;
$$ LANGUAGE sql STABLE;
```

应用连接时执行 `SET app.tenant_id = ?`，RLS 策略统一引用该函数。

### 4.2 策略模板（基线迁移实读）

```sql
CREATE POLICY p_{表名}_tenant ON {表名}
    USING      (tenant_id = sys_current_tenant())
    WITH CHECK (tenant_id = sys_current_tenant());
```

- `USING` 管**读**（行可见性）· `WITH CHECK` 管**写**（写入必须属于本租户）
- 命名约定 `p_{表名}_tenant`，与表名一一对应
- **当前已落地 10 条 POLICY**，覆盖 `sys_user` / `sys_dept` / `sys_role` 等平台表及 `dt_*` / `ag_*` 表

### 4.3 建表纪律

| 规则 | 说明 |
|---|---|
| 每张业务表必备租户列 | `tenant_id BIGINT NOT NULL` |
| 唯一索引**必须以 `tenant_id` 打头** | 如 `uk_sys_user_username ON sys_user (tenant_id, username) WHERE is_deleted = 0` |
| 普通索引同样带租户列 | 如 `idx_sys_user_dept ON sys_user (tenant_id, dept_id)` |
| 迁移脚本与代码同 PR 提交 | 命名 `V{yyyyMMddHHmm}__{域}_{描述}.sql`，**禁止修改已执行的历史脚本** |

## 五、租户上下文传播（跨线程/跨进程/跨产品）

| 场景 | 传播方式 | 强制要求 |
|---|---|---|
| HTTP 入站 | 网关校验 JWT 后注入 `X-Tenant-Id` | **禁止从请求参数取租户** |
| 同步方法内 | ThreadLocal 隐式可用 | — |
| **异步 / 虚拟线程 / 线程池** | `TenantContext.wrap(principal, task)` | **必须显式传播** |
| 领域事件消费 | 从 `event.tenant_id` 恢复上下文 | 消费方按此隔离 |
| 服务间调用 | 透传 `X-Tenant-Id` / `X-Trace-Id` | 缺失即拒 |
| **智能体工具调用** | **元枢工具网关注入**租户与用户上下文 | 智能体不得跨租户检索 |

> 该链路与 `03-api` 附录 B 的 HTTP 头约定一一对应，两份文档须保持同步。

## 六、隔离测试套件（六项，合并前必跑）

实现：`lingxi-ops/scripts/verify-tenant-isolation.sh <租户A_TOKEN> <租户B_TOKEN> [API_BASE]`（**只读**，仅写测试报告）

| # | 检查 | 判据 |
|---|---|---|
| ① | 数据层越权 | 以租户 A 的 Token 访问租户 B 的资源 ID → **必须 403 / 404** |
| ② | 列表层归属 | 租户 A 的列表接口 → 结果集**必须 100% 属于租户 A**（抽样断言） |
| ③ | 检索层（含向量） | 租户 A 搜索 → **不得召回租户 B 任何记录**（含向量检索） |
| ④ | 智能体层 | 智能体以租户 A 上下文调用工具 → 不得读取租户 B 数据 |
| ⑤ | 导出对账 | 导出行数**必须等于**本租户计数 |
| ⑥ | **RLS 直连校验** | 绕过应用层直连数据库查询 → **RLS 必须拦住** |

> ⑥ 是对第 ③ 道防线的**独立验证** —— 前 ⑤ 项都可能被应用层拦截"意外通过"，只有直连才能证明 RLS 真的生效。
> 覆盖策略：**新增任何带租户数据的接口，必须同时提交隔离测试用例**，视为契约的一部分，缺失则 CI 失败。

## 七、**三产品责任划分（本次新增重点）**

四道防线的**实现与维护全部由元枢提供**，灵犀 / 开物**只继承、不重复实现** —— 这是硬约束 2「集群不得自建底座能力」在租户隔离上的具体落地。

| 能力 | 提供方 | 集群侧义务 |
|---|---|---|
| 租户上下文 `TenantContext` | 元枢 `yuanshu-platform` | 异步场景必须 `wrap()` 显式传播 |
| 租户插件与白名单 | 元枢 | 新表默认带租户列；申请白名单须架构组评审 |
| RLS 策略 | 元枢（元枢表）/ 集群（自己域的表，**策略模板仍由元枢统一**） | 建表时必须同时写 RLS 策略 |
| 行级数据权限 `DataScope` | 元枢 | **不得自定义口径**（枚举 5 值平台统一定义） |
| 隔离测试套件 | 元枢提供脚本 | 集群新增接口必须补用例 |
| Keycloak Realm ↔ 租户 | 元枢 | **Realm 天然对应租户**，集群不另建 IdP |

### 跨产品场景

| 场景 | 规则 |
|---|---|
| 开物接入 | 经 `AgentRegistrationApi` 注册时由 `OwnerProduct`（LINGXI / KAIWU）决定归属租户；租户边界**不因产品而重划** |
| 两集群共用底座 | 同一租户在两侧看到的是**同一份隔离数据**，元枢不做产品维度的二次隔离 |
| 元枢变更 | **必须前向兼容**（硬约束 3）：底座动一次两个集群都要回归 → 走版本 + 灰度 |
