**统一母题：一个"通"字**

| 产品 | 通什么 | 覆盖范围 |
|---|---|---|
| **灵犀** | **通人** —— 通客户、通市场、通内容、通服务 | 企业之外 |
| **开物** | **通物** —— 通产品、通工序、通设备、通能源与碳 | 企业之内 |
| **元枢** | **通源** —— 通数据之源、通语义之源、通智能之源 | 两者之下 |

**对外一句话**：**灵犀通人，开物通物，元枢通源。**

**体系化的三个理由**（为什么这三个名字是一套）：

| 维度 | 一致性 |
|---|---|
| 结构 | 均为双音节，均为"限定字 + 主体字"（灵/开/元 + 犀/物/枢） |
| 音形 | 三个名字均无生僻字，英文态统一用拼音（Lingxi / Kaiwu / Yuanshu），国际注册撞名概率最低 |
| 意象 | 感 / 造 / 源，互补不重叠——合起来正好是"感知—造物—根基"的完整闭环 |

**为什么弃用"天工"**：① 市场上存在名称相近的工业相关品牌，独特性不足；② 与天能企业名的关联过强，不利于作为独立产品对外销售；③ 只取"开物"二字，保留文化基因而切断绑定。

## 二、三产品定位与核心功能

### 2.1 总览

| 维度 | 灵犀 | 开物 | 元枢 |
|---|---|---|---|
| **一句话定位** | 营销服智能体集群 | 工业智能体集群 | 数智底座 |
| **服务对象** | CEO、五大总监、一线业务员 | 质量/能源/设备负责人、生产与合规管理者 | 前两者的产品团队与客户 IT |
| **覆盖范围** | 企业之外：客户 · 市场 · 内容 · 服务 | 企业之内：产品 · 工序 · 设备 · 能源 · 碳 | 两者之下：数据 · 语义 · 智能体 · 租户 |
| **交付形态** | SaaS 标准化，开箱即用 | 轻交付（数据只读接入 + 行业包配置） | 平台能力输出（内部共用 + 可选私有化） |
| **计费方式** | 按账号/模块订阅 | 按工厂 + 产品型号 + 用量订阅，可叠加效果分成 | 内部成本中心；对外按租户/用量 |
| **可见性** | 直接面向客户业务人员 | 直接面向客户业务人员 | **不直接面向业务人员**（能力层） |

### 2.2 灵犀 —— 营销服智能体集群

**定位**：面向制造型企业的出海营销服智能体集群。以三类数据整合为壁垒，用"人工运营底座 + 智能体增强"的人机融合方式，把获客、触达、转化、服务四环节的效率和资产同时提升。

**核心功能（四组）**：

| 组 | 内容 |
|---|---|
| ① 人工运营底座 | 客户中心 · 商品中心 · 订单交付 · 售后服务 · 营销中心 · 知识中心（保证智能体未就绪时业务也不停摆） |
| ② 智能体集群 | 6 个智能体：客户开发 / 市场分析 / 内容创意 / 社媒运营 / 营销客服 / 经营分析 |
| ③ 决策与治理 | 五角色工作台 · 经营分析 · 配置中心 |
| ④ 三条增补产品线 | 产品服务化延伸 · 出海合规数据披露 · 场景达标服务包 |

**攻坚智能体**（按优先级）：营销客服 4.70 → 客户开发 4.50 → 内容创意 4.35。

**明确不做**：生产侧任何模块、通用 ERP/CRM 替代、定制化项目交付。

### 2.3 开物 —— 工业智能体集群

**定位**：面向制造型企业的工业智能体集群。把企业**已经在 MES / QMS / EMS / ERP 里、但用不起来**的数据，变成可核算、可追溯、可优化的合规资产与运行智能。

**核心功能（三层 + 一条链）**：

| 层 | 内容 |
|---|---|
| ① 场景智能体集群 | 5 个智能体：质量追溯 / 能碳 / 设备健康 / 生产效率 / 生产安全 |
| ② 行业包层 | 五件套：物料与产品语义字典 · 工序与工艺路线模板 · 碳核算因子库与方法学映射 · 质量标准与追溯数据项模板 · 设备型号与健康特征库 |
| ③ 一条链 | 一次数据采集 → 同时产出质量档案 + 碳足迹 + 数字护照（同一产品 ID） |

**攻坚智能体**（按优先级）：质量追溯 4.60 → 能碳 4.50 → 设备健康·产品侧 3.90。
**收敛**：生产效率（只做订单—生产—交付协同建议，不做排程执行）。
**降级为能力组件**：生产安全（不独立立项）。

**五条红线**：不碰 OT 采集 · 不碰产线控制 · 不碰装备本体 · 不做数字孪生工厂 · 不做排程执行。

### 2.4 元枢 —— 数智底座

**定位**：面向制造行业的统一数据与 AI 底座。为灵犀与开物提供**数据、语义、智能体生产、多租户**四类公共能力；对外不承载业务界面。

#### 核心功能一：制造行业大数据

| 能力 | 内容 |
|---|---|
| 外部数据 | 全球 B 端企业大数据（企业实体档案、域名/地址/行业、关系网络）、互联网与社媒数据、贸易与海关数据 |
| 内部数据 | 企业业务数据（营销服）+ 工业数据（产品/工序/设备/能源/碳） |
| 数据链路 | 采集与只读接入 → 清洗与质量规则 → 实体消歧与主数据（MDM）→ 入湖与分层存储 → 指标口径与血缘 |
| 资产化 | 数据资产目录 · 标签体系 · 数据服务 API（统一出口，供两个集群调用） |

#### 核心功能二：制造行业语义管理

| 能力 | 内容 |
|---|---|
| 行业本体 | 五类语义：**产品 / 物料 / 工序 / 设备 / 能源**（含质量与碳扩展字段） |
| 术语与标准 | 行业术语字典 · 单位与量纲 · 编码体系（物料码、工序码、设备码） |
| 指标口径中心 | 同名指标统一定义，杜绝"同名不同义"——这是"同源无影子数据"的基础 |
| 实体消歧引擎 | 域名 > 名称规范化 > 地址+行业（相似度 ≥0.85）；前两级自动归并、第三级人工队列；**归并可逆** |
| **行业包管理** | 行业包（五件套）的注册 / 版本 / 扩展 / 下发——**开物跨行业复制的机制所在** |
| 语义服务 | 面向智能体与业务系统的标准查询接口 |

#### 核心功能三：智能体开发 / 维护 / 迭代

| 环节 | 能力 |
|---|---|
| **开发** | 智能体工厂（脚手架、模板、单/多智能体编排）· 技能与工具：MCP 工具注册治理、技能包、工具权限白名单（三层拦截第一层）· 知识与提示词版本管理 |
| **治理** | A0~A3 自主度分级配置 · 越界规则与"不做清单" · 三层边界拦截 · 审批流 · 双通道同源校验 |
| **评测** | 评测集与回归测试 · 越界测试 · 模拟考场（真实异常压测）· 上线门禁 |
| **维护** | 运行调度 · 任务队列与并发控制 · Trace 与运行监控 · 效能评估（采纳率 / 人工介入率 / 节省工时 / 成本） |
| **迭代** | 版本发布与灰度 · 回滚 · 效果反馈闭环 |
| **模型网关** | 多模型路由（场景码路由表）· 降级链 · Token 配额与成本计量 |

#### 核心功能四：多租户管理

| 能力 | 内容 |
|---|---|
| 租户生命周期 | 开通 / 配置 / 停用；Realm 对应租户 |
| 权限 | 功能级 / 行级 / 字段级三层（Casbin） |
| 数据隔离四道防线 | ① 租户拦截器自动注入 tenant_id ② 数据权限过滤 ③ PostgreSQL RLS 兜底 ④ 隔离测试套件（6 项，合并前必跑） |
| 审计 | 操作审计 · 智能体行为审计 · 数据访问审计（全留痕、可追溯） |
| 计费与配额 | 用量计量 · 额度控制 · 套餐管理 |

## 三、三产品关系：一底两翼

```
        ┌────────────────────┐        ┌────────────────────┐
        │       灵犀          │        │       开物          │
        │  营销服智能体集群     │        │  工业智能体集群      │
        │  ──────────────    │        │  ──────────────    │
        │  6 个智能体         │        │  5 个场景智能体      │
        │  通人（企业之外）    │        │  通物（企业之内）    │
        └─────────┬──────────┘        └──────────┬─────────┘
                  │                              │
                  └──────────────┬───────────────┘
                                 │  统一调用
        ┌────────────────────────▼──────────────────────────┐
        │                    元枢  数智底座                   │
        │  ┌──────────┬──────────┬───────────┬───────────┐  │
        │  │ 大数据    │ 语义管理  │ 智能体工厂  │ 多租户     │  │
        │  │ 通源      │ 行业包    │ 开发运维迭代 │ 隔离审计   │  │
        │  └──────────┴──────────┴───────────┴───────────┘  │
        └───────────────────────────────────────────────────┘
```

**组织表述**：**一底两翼**。元枢为底（源），灵犀与开物为两翼（感与造）。

### 3.1 边界判定规则（一条，用于所有争议）

> **能被两个集群共用的能力 → 下沉到元枢；只服务单个集群业务的能力 → 留在集群内。**

| 事项 | 归属 | 判定依据 |
|---|---|---|
| 数据接入与清洗 | 元枢 | 两个集群都需要 |
| 业务数据的**写入**与业务语义解释 | 所属集群 | 只有该集群懂这个业务 |
| 指标口径定义 | 元枢 | 必须全局唯一 |
| 行业本体（五类语义） | 元枢 | 开物的行业包建立在它之上 |
| 行业包内容（碳因子库等） | 元枢托管，开物维护 | 资产归底座、内容归业务 |
| 智能体运行时（自主度/拦截/审批） | 元枢 | 两个集群共用 |
| 智能体的业务逻辑与知识 | 所属集群 | 与具体业务强绑定 |
| 客户实体消歧 | 元枢 | 两产品共用同一份企业档案 |
| 权限与会话 | 元枢 | 一套身份、一套权限 |

### 3.2 三者接口

| 接口 | 内容 |
|---|---|
| **唯一数据接口** | **同一个产品 ID**：开物产出的合规数据（质量档案/碳足迹/护照），灵犀用于对客披露与服务运营 |
| **唯一身份接口** | 元枢统一会话与权限，三产品单点登录 |
| **唯一语义接口** | 所有产品读同一份指标口径与行业本体，不允许私建 |

## 四、硬约束（四条）

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | **元枢不得承载业务界面** | 一旦藏业务逻辑，就会变成谁都不敢改的大泥球 |
| 2 | **集群不得自建底座能力** | 一旦各建一套数据/权限/MCP，多租户隔离与"同源无影子数据"立刻失效 |
| 3 | **元枢变更须前向兼容** | 底座动一次，两个集群都要回归——变更必须走版本与灰度 |
| 4 | **两个集群销售与交付团队分离** | 灵犀是 SaaS 节奏，开物是轻交付节奏，共用团队会让 SaaS 被项目拖死 |

## 五、落地节奏

| 阶段 | 灵犀 | 开物 | 元枢 |
|---|---|---|---|
| **第一阶段** 0~6 月 | 营销客服智能体上线（3 家客户） | 质量追溯：电池行业包 V1 + 单条产品线质量档案跑通 | 语义管理（五类本体 V0）+ 多租户四道防线 + 智能体工厂 MVP |
| **第二阶段** 6~12 月 | 客户开发智能体（消歧 ≥85%、归因闭环） | 能碳：单产品碳足迹核算 + 报告生成 | 大数据（B 端实体消歧引擎）+ 评测与回归 + 模型网关 |
| **第三阶段** 12~18 月 | 内容创意智能体 | 设备健康·产品侧（SOH） | 行业包管理 + 效能评估 + 对外开放（第三方智能体接入） |

**优先级铁律**：**元枢的能力只按集群的实际需求建设**，不做"通用平台"式的超前投资。第一个半年元枢只做四件事——语义本体、多租户、智能体工厂、模型网关。
