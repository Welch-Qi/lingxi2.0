## 一、产品定位

### 1.1 定位表述

> **面向中小制造企业，以三类数据的整合沉淀为技术壁垒，提供人机融合 Native 的出海营销服数智化平台。**

一句话价值主张：**让中小制造企业用得起、跑得动、越用越强——人把业务搬上线，AI把效率提上去，数据把壁垒垒起来。**

### 1.2 目标客户

| 维度   | 界定                                          |
| ---- | ------------------------------------------- |
| 企业规模 | 年营收 1000 万 ~ 10 亿的中小制造企业                    |
| 核心特征 | 有出海需求或已在做外贸；数字化投入低（无预算自建系统）；依赖人工作业、报表靠手工汇总  |
| 用户跨度 | 从外贸新手（需要"告诉我怎么做"）到外贸熟手（需要"帮我做得更快"）          |
| 决策链  | CEO（老板）→ 五大总监（产品开发/渠道运营/内容创意/客户销售服务）→ 一线业务员 |

### 1.3 三类客户痛点与产品应答

| 客户痛点       | 现状                 | 灵犀的应答                                  |
| ---------- | ------------------ | -------------------------------------- |
| **数字化投入低** | 买不起大厂方案，也没人实施      | 开箱即用 SaaS + 人工运营底座（先能用）+ 智能体增强（后好用）    |
| **用户运营弱**  | 客户信息散在业务员手机里，人走客户丢 | 客户中心统一沉淀 + 企业实体档案 + 全旅程记录，客户资产变成企业资产   |
| **有出海需求**  | 不懂市场、语言不通、获客无门     | 市场情报（看清市场）+ 内容创意与社媒运营（多语言触达）+ 客户开发（找人） |
| **决策靠感觉**  | 经营数据靠月底手工报表，滞后且失真  | 数据即时沉淀 + 经营分析智能体（问答式取数、异常归因、风险预警）      |

### 1.4 三个 "Native" 的产品化内涵

| Native 维度        | 含义                   | 落地要求                             |
| ---------------- | -------------------- | -------------------------------- |
| **AI Native**    | 智能体内嵌于业务流，而非外挂工具     | 智能体产出直接写入业务表（线索/内容/工单/记录），无需人工搬运 |
| **Data Native**  | 数据不是事后统计，而是业务发生的即时沉淀 | 每一次人工操作、每一次智能体执行都即时入湖，随时可用于分析与AI |
| **Human Native** | 界面按角色工作习惯设计，而非按系统模块  | 五个角色各有专属工作台，默认页即当日该做的事           |

### 1.5 核心价值主张（分角色）

| 角色           | 他关心的                       | 灵犀给他的                          |
| ------------ | -------------------------- | ------------------------------ |
| **CEO**      | 生意健康不健康、增长从哪来、风险在哪、AI投入值不值 | 经营总览 + 风险预警 + 客户资产统计 + 智能体人效报告 |
| **产品开发总监**   | 开发什么产品、卖给哪个市场、客户反馈是什么      | 高潜力产品机会 + 商品数据完整度 + 售后质量反馈     |
| **渠道运营总监**   | 渠道结构健康不健康、履约顺不顺、准时不准时      | 订单与OTD异常看板 + 渠道产出排行 + 交付风险预警   |
| **内容创意总监**   | 内容产出效率与质量、多语言本地化、效果好不好     | 内容日历 + 待审内容 + 效果排行 + 账号健康度     |
| **客户销售服务总监** | 线索够不够、转化高不高、客户资产有没有沉淀      | 线索池 + 今日跟进 + 商机漏斗 + 售后工单       |
| **一线业务员**    | 今天该跟进谁、话怎么说、单子什么时候成        | 一个工作台看完全部待办；AI替写开发信、替做记录、替提醒   |

## 二、核心功能

> 灵犀系统的功能围绕**十三个一级菜单**组织，每一菜单对应一类明确的业务对象或治理对象，业务人员按"我要处理什么"直接进入，不需要先理解系统结构。  
> 其中客户域按**三层对象模型**拆为三个并列一级菜单：**客户中心**（企业主体）、**商机中心**（单次采购机会）、**线索中心**（原始名单）——对象不同、生命周期不同、责任人不同，故不塞进同一个菜单。三者关系见第三章。

### 2.1 工作台 —— 我的今日

| 能力     | 说明                                               |
| ------ | ------------------------------------------------ |
| 角色化首页  | 按五个角色自动适配：CEO 看经营总览与风险；总监看本域指标与团队；业务员看今日待跟进与业绩进度 |
| 统一待办   | 跨模块汇总待处理事项（待跟进客户、待审内容、异常订单、售后工单），按紧急度智能排序        |
| 我的 KPI | 本岗位核心指标卡（业绩进度、转化率、准时率、内容产出等），带趋势对比               |
| 通知与提醒  | 询盘提醒、任务状态通知、系统消息、业务预警分级推送                        |
| 智能助手入口 | 自然语言问答与任务委派（如"帮我分析德国市场""给这批线索发一轮开发信"）            |

### 2.2 客户中心 —— 客户资产的家

> **承载对象**：客户 Account（企业 / 组织主体）· 联系人。  
> 线索与商机已独立为一级菜单（见 2.3 / 2.4），客户中心只保留"企业主体 + 关系人 + 全旅程记录"三类内容，**不在本菜单重复维护线索与商机**。

| 能力        | 说明                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 客户档案      | 客户基础信息（名称 / 类型 / 价值分层 / 行业 / 规模 / 区域 / 负责人 / 来源）、标签；与「企业实体中心」关联，一企一档                                                                                          |
| 客户类型      | **新潜客户 / 首次成交客户 / 复购客户**，判定口径是**客户级成交次数**（0 次 / 1 次 / ≥2 次），与「最近成交时间」同源。**弱化潜客**：不单设「潜客」对象，线索核验合格后直接建立客户主体，"还没买过 / 买过一次 / 反复买"只是客户类型的状态；已有成交的客户新建商机即增购 / 复购商机 |
| 客户价值分层    | **战略大客户 S / 重点客户 A / 常规客户 B / 小微客户 C / 休眠客户 D**。客户本体的**长期属性**，与单条商机无关，是差异化服务资源的配置依据，每季度复核                                                                     |
| 联系人管理     | 多联系人维护（决策人 / 采购 / 技术 / 财务）、角色标注、多通道联系方式；避免"人走客户丢"                                                                                                             |
| 跟进记录      | 跟进时间 / 方式 / 结果 / 下一步的标准化记录，支持沟通后自动生成草稿；全旅程时间轴                                                                                                                 |
| 客户 360 视图 | 融合外部数据（采购能力）+ 内部数据（沟通 / 商机 / 订单 / 售后）的全息档案；**线索与商机以关联列表呈现（一跳可达），不在本菜单重复维护**。商机列表与跟进记录以**页签**切换，两者都是列表形态（跟进记录四列：跟进时间 / 跟进人 / 跟进小结 / 下次跟进时间）                    |
| 公海与健康度    | 自动退公海规则（N 天无跟进自动回收）、客户健康度评分与流失风险标记                                                                                                                            |
| 智能体增强     | 营销客服智能体自动生成跟进记录；智能建档自动补全信息；客户开发智能体产出的线索进入**线索中心**而非此处                                                                                                         |

### 2.3 线索中心 —— 从名单到合格线索

> **承载对象**：线索 Lead（原始联系资料，**未经核验**）。  
> **线索不是客户**：可能只是个人、空号、错误号码或无关信息，尚未确认是真实企业主体，也无法确认是否有需求。核验合格才转化为客户主体，不合格即归档，**不保留**。

| 能力      | 说明                                                                                                          |
| ------- | ----------------------------------------------------------------------------------------------------------- |
| 全渠道线索归集 | 官网留资 / 展会 / 广告投放 / 转介绍 / 渠道 / 主动开发 / 名单采购 / 智能体开发，全渠道集中进同一个池子                                               |
| 线索字段与登记 | 线索来源（lead_source）、联系方式（lead_contact：电话 / 微信 / 邮箱）、留资时间（lead_time）、线索状态（lead_status）；线索阶段**仅存联系信息**，不存企业档案字段 |
| 线索状态流转  | **待联系 → 已转化 / 无效**。待联系＝尚未建联；已转化＝核验合格已生成客户主体；无效＝空号 / 错误 / 无关信息，归档丢弃                                          |
| 线索分配与认领 | 手工登记、认领、指派、公海回收，支持批量分配；分配规则来自配置中心「销售配置」                                                                     |
| 查重防撞单   | 对客户名称、域名、地址、官网多维查重，逻辑统一走**企业实体中心消歧规则**（域名 > 规范化名称 > 地址+行业）                                                  |
| 线索评分与分级 | 结合企业实体数据与行为数据自动评分分级，业务员优先跟进最可能成的                                                                            |
| 线索转化    | **核验合格 → 一键转化生成客户主体**（写入客户中心），线索状态置「已转化」并回链客户 ID（幂等，禁止重复建客户）；不合格直接归档                                        |
| 智能体增强   | 客户开发智能体批量检索、首触与多轮跟进、自动初筛与评分；社媒运营智能体识别询盘自动转线索                                                                |

### 2.4 商机中心 —— 每一次采购机会

> **承载对象**：商机 Opportunity（依附于客户主体的**单次采购机会**）。  
> 商机是"这一单生意"，**不是企业**；**1 个客户可同时有 N 条商机**（新购 / 增购 / 复购），商机与客户分开维护。

| 能力      | 说明                                                                                                                                                                                           |
| ------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 商机创建与归属 | 商机**必须挂到某个客户主体下**（customer_ref）；商机名称、商机来源、商机负责人、关联客户                                                                                                                                         |
| 生命周期阶段  | **首触 → 跟进培育 → 方案报价 → 商务谈判 → 已签约 → 交付中 → 已验收**；兜底关闭状态「**流失关闭**」（任意阶段项目终止 / 需求取消 / 选竞品 / 明确放弃）；阶段定义可由配置中心按租户覆盖。**不设「待建联」**（V2.1.1 起）：商机一旦报备落库就必然已指定跟进人、已进入接触，再留一段"还没接触上"既与报备动作自相矛盾，也会让漏斗首段恒为空档 |
| 意向等级    | **A 高意向 / B 中意向 / C 低意向 / D 无效**，**只评估未关闭商机的购买意愿**；按 BANT 四要素判定，标 A 为硬门槛（确认预算 ＋ 找到决策人 ＋ 明确采购时间 ＋ 需求真实）                                                                                       |
| 重评机制    | 处于「跟进培育 / 方案报价」的商机**每 30 天强制重评**意向等级；客户情况重大变化（预算取消 / 换人 / 延期）即时更新，避免商机躺平在 A 级                                                                                                                |
| 金额与预测   | 预计成交金额、预计成交时间，用于销售预测与漏斗金额汇总                                                                                                                                                                  |
| 跟进节奏    | 下次跟进时间（SLA 触发依据：A 级 7 天、B 级 30 天）、最近跟进时间、跟进记录                                                                                                                                                |
| 商机过程    | BANT 成立理由、竞品情况、商机备注；阶段停留时长统计与超时预警                                                                                                                                                            |
| 关闭与回流   | **成交关闭**（验收通过）→ 客户类型自动更新为**首次成交客户**（该客户此前从未成交）或**复购客户**（该客户此前已有成交），可继续挖掘增购与复购商机；**流失关闭** → 归档并记录流失原因，客户主体保留、价值分层可能下调                                                                         |
| 智能体增强   | 营销客服智能体生成商机推进建议与跟进提醒；经营分析智能体做漏斗分析与赢 / 输单归因                                                                                                                                                   |

### 2.5 商品中心 —— 商品与素材的单一事实源

| 能力      | 说明                                     |
| ------- | -------------------------------------- |
| 商品主数据   | SKU、品名、规格、品牌、分类、HS编码、多语言信息             |
| 产品素材库   | 图片/视频上传、分类、打标、多语言版本、与 SKU 关联（内容创意的弹药库） |

| 智能体增强   | 内容创意智能体引用素材生成多语言内容；AI 补全 HS 编码与属性缺失项   |

### 2.10 经营分析 —— 让决策有依据

## 三、核心对象模型与模块关联

> 客户域的对象划分决定菜单边界、权限边界与数据口径：**先定对象，再定模块**。

### 3.1 三层对象模型（选型1 · 弱化潜客）

客户域采用标准三层对象：**线索 Lead → 客户 Account + 商机 Opportunity**。

```
                        核验合格
  ┌──────────────┐       转化      ┌───────────────┐
  │   线索 Lead   │ ─────────────→ │ 客户 Account   │
  │  原始联系资料  │                │  企业/组织主体  │
  │  未经核验      │                └───────┬───────┘
  └──────┬───────┘                        │ 挂载 1 : N
         │ 不合格                          ▼
         ▼                       ┌────────────────────┐
     归档丢弃                     │ 商机 Opportunity    │
                                 │  单次采购机会        │
                                 └─────────┬──────────┘
                                           │ 已签约 / 已验收
                                           ▼
                                 ┌────────────────────┐
                                 │     订单 Order      │
                                 └────────────────────┘
```

| 对象     | 英文          | 定义                                                         | 关键挂载                                                                         | 状态与流转                                                                   | 归属模块          |
| ------ | ----------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------- |
| **线索** | Lead        | 原始联系资料，**未经核验**。可能只是个人、空号、错误号码或无关信息，尚未确认是真实企业主体，也无法确认是否有需求 | 线索来源、联系方式、留资时间、线索状态                                                          | 待联系 → 已转化 / 无效；不合格归档，**不保留**                                            | **线索中心**（2.3） |
| **客户** | Account     | 企业 / 组织主体，全公司档案的统一载体                                       | 客户名称、**客户类型（新潜 / 首次成交 / 复购）**、**客户价值分层 S/A/B/C/D**、行业、规模、区域、负责人、统一联系人档案、历史订单 | 新潜客户 → 商机推进 → 首次成交客户 → 复购客户。**分类维度只有"类型 + 价值"两个，不设客户阶段、不设客户意向**（见 §3.4） | **客户中心**（2.2） |
| **商机** | Opportunity | 依附于客户主体的**单次采购机会**，是"这一单生意"，**不是企业**                       | 归属客户、商机名称、**意向等级 A/B/C/D**、**生命周期阶段**、预计成交金额与时间、商机关闭结果                       | 首触 → 跟进培育 → 方案报价 → 商务谈判 → 已签约 → 交付中 → 已验收；或流失关闭                         | **商机中心**（2.4） |

**挂载原则**：客户价值分层挂**客户**层；商机意向等级与生命周期阶段挂**商机**层；线索只承载来源、联系信息与核验状态。

> **交付批次**：客户中心、商机中心进 **P0**（一期）；线索中心进 **P2**（二期）。

### 3.2 不设「潜客」对象

**结论：客户域只有三层对象，不设「潜客（Prospect）」。**

- 线索核验合格 → **直接建立客户主体**，不存在"潜客"中间对象；
- 客户只按**客户类型**（`customer_type`）分三档：**新潜客户 / 首次成交客户 / 复购客户** —— "潜"指的是"还没买过"，它是**客户类型的一个取值**，不是一个独立对象；
- 客户域的表名、字段名、菜单名一律不出现"潜客"。

### 3.3 四条跨模块链路

| 链路           | 触发条件                    | 源对象变化              | 目标对象变化                                                   | 约束                                                                                |
| ------------ | ----------------------- | ------------------ | -------------------------------------------------------- | --------------------------------------------------------------------------------- |
| **① 线索转化**   | 建联核验确认是真实企业主体且有需求       | 线索状态：待联系 → **已转化** | 新建客户主体（客户类型＝**新潜客户**）；客户来源＝线索来源                          | **一条线索只允许转化一次**；回链 `converted_customer_id`；企业实体中心查重命中则复用既有 `entity_id`，**不重复建客户** |
| **② 客户挂商机**  | 销售在客户下创建商机              | 商机创建，阶段＝**首触**     | 客户「商机数」计数 +1                                             | 商机**必须**有 `customer_ref`，**禁止孤儿商机**；一个客户可有 0 / 1 / N 条商机                          |
| **③ 商机回流客户** | 商机进入**已验收**（成交关闭）       | 商机关闭结果＝成交关闭        | 客户类型 → **首次成交客户**（此前从未成交）/ **复购客户**（此前已有成交）；客户「最近成交时间」刷新 | 该客户名下其他未关闭商机的在谈状态不受影响                                                             |
| **④ 商机转订单**  | 商机**已签约**（合同签署 / 收到预付款） | 商机移交交付团队           | 生成订单，进入 OTD                                              | 一条商机可对应多张订单（分批交付）；订单回链 `opportunity_id`                                           |


### 3.4 客户不设阶段，也不设意向

**结论：客户只有「客户类型 + 客户价值分层」两个分类维度，不派生客户阶段、不评客户意向。**

- **不设客户阶段**：阶段是**商机**的属性（这一单在流程上走到哪一步），不是客户主体的属性。V2.1 曾把客户名下商机的阶段「归并派生」成客户所处阶段（取推进最远的一条），用于客户列表的生命周期筛选；**V2.1.1 起取消**，理由三条：
  1. 归并规则本身需要解释 —— "推进最远"是哪种远？已关闭的算不算？看列表的人要先学会这条规则才能读懂那一列；
  2. 一个客户名下常并存多条处于不同阶段的商机（新购 / 增购 / 复购），归并成单一阶段必然丢信息；
  3. 客户列表真正要回答的是"这个客户算什么"（类型）与"值多少"（价值分层），"推进到哪"留给商机中心。
- **不设客户意向**：意向等级是**单次采购机会**的购买意愿（仅评未关闭商机），挂在商机上；客户层只有长期价值分层 S/A/B/C/D。两套 A/B/C/D 不可混用，见 §3.5。
- **筛选口径**：客户列表顶部**同一行**给两个筛选维度 —— **客户类型**（全部 / 新潜客户 / 首次成交客户 / 复购客户）+ **客户价值分层**（全部 / 战略大客户 S / 重点客户 A / 常规客户 B / 小微客户 C / 休眠客户 D），最右是高级筛选开关（客户编码 / 名称、建档时间、国家、城市）。

### 3.5 两套 A / B / C / D 不可混

客户域同时存在两套字母等级，**维度、对象、更新频率均不同，报表与筛选中禁止混用**：

| | **意向等级** | **价值分层** |
|---|---|---|
| **取值** | A 高意向 / B 中意向 / C 低意向 / D 无效 | S 战略大客户 / A 重点客户 / B 常规客户 / C 小微客户 / D 休眠客户 |
| **挂在哪** | **商机** | **客户** |
| **评什么** | 这一单的**购买意愿**（仅评未关闭商机） | 这个客户的**长期价值**（与单条商机无关） |
| **判定依据** | BANT 四要素（预算 / 决策人 / 需求 / 时间） | 营收贡献 / 增长潜力 / 决策链复杂度 |
| **复核节奏** | 跟进培育、方案报价阶段**每 30 天强制重评** | **每季度复核一次** |
| **变了会怎样** | 只影响这条商机的跟进 SLA 与资源投入 | 只影响这个客户的服务资源配置 |
| **关闭之后** | 商机关闭即**不再评**——成交、复购都不是意向等级 | **不随单条商机关闭而改变** |

**标 A 硬门槛**：必须同时满足「确认预算 ＋ 找到决策人 ＋ 明确采购时间 ＋ 需求真实」四项，缺一不可。

### 3.6 统计口径

| 口径 | 规则 | 说明 |
|---|---|---|
| **销售漏斗** | 只统计**未关闭商机**（首触 / 跟进培育 / 方案报价 / 商务谈判），排除已签约、交付中、已验收、流失关闭 | 已签约及之后不属于"待赢的生意" |
| **增购 / 复购识别** | 拆成两问：**这客户成交过没有** × **这个意向产品他买过没有** —— **首购**＝客户从未成交（`last_deal_at` 为空）；**复购**＝客户已成交且该意向产品在其成交产品集内；**增购**＝客户已成交但该产品未买过 | 判据落在**成交事实**（客户级字段 + 成交侧商机的产品集），**不从 `customer_type` 反推** —— 那是季度复核得来的属性，一次复评会让历史商机的采购性质集体翻转。又因列表是**第 1 页切片**，**禁止用"切片内有没有已成交商机"当判据** |
| **线索转化率** | 分子＝线索状态「已转化」条数；分母＝期内全部线索（**含无效**） | 无效线索同样消耗获客成本 |
| **客户资产统计** | 以**客户主体**计数（一企一档），不以线索数或商机数计 | 与「企业实体中心」口径一致 |

### 3.7 对象与菜单的对应

| 一级菜单 | 对象 | 主责角色 | 日常动作 | 交付批次 |
|---|---|---|---|---|
| **客户中心** | 客户 Account | 客户经理 | 建档、维护关系人、跟进、看 360 | **P0** |
| **商机中心** | 商机 Opportunity | 销售 | 推进阶段、评意向、控 SLA、报金额 | **P0** |
| **线索中心** | 线索 Lead | 客户开发 / 销售助理 | 认领、建联、核验、转化或丢弃 | **P2** |

## 四、产品架构

### 4.1 四层架构

```
┌───────────────────────────────────────────────────────────────────────────┐
│  L4  角色工作台层                                                          │
│      CEO工作台 ｜ 产品开发总监 ｜ 渠道运营总监 ｜ 内容创意总监 ｜ 客户销售服务总监 │
│      设计原则：默认页 = 当日工作，千人千面                                    │
├───────────────────────────────────────────────────────────────────────────┤
│  L3  智能体层                                                              │
│      客户开发 ｜ 市场分析 ｜ 内容创意 ｜ 社媒运营 ｜ 营销客服 ｜ 经营分析        │
│      智能体中心（配置/调度/监控/效能） ｜ 协作总线 ｜ 自主度分级                │
│      设计原则：增量替代，产出直接入业务表，人随时可接管                          │
├───────────────────────────────────────────────────────────────────────────┤
│  L2  人工运营底座（一级菜单直达 · 人机双通道）                                   │
│  客户域三中心：客户中心 ｜ 商机中心 ｜ 线索中心                                  │
│  业务域：商品中心 ｜ 订单交付 ｜ 售后服务 ｜ 营销中心 ｜ 市场情报 ｜ 经营分析    │
│  设计原则：业务对象导向，任何能力都有不经过智能体的直达入口                      │
├───────────────────────────────────────────────────────────────────────────┤
│  L1  数据底座（壁垒层）                                                     │
│  三类数据源 → 企业实体中心（一企一档）→ 数据资产四层（企业图谱/产品图谱/标签/指标）│
│  设计原则：越用越厚，客户迁移成本递增                                          │
├───────────────────────────────────────────────────────────────────────────┤
│  L0  技术底座                                                              │
│  模型/技能/MCP ｜ 多租户 ｜ 权限 ｜ 全球化 ｜ 企业公约 ｜ 审计                 │
└───────────────────────────────────────────────────────────────────────────┘
```

**四层的分工逻辑**：L0 决定"能不能跑"，L1 决定"有没有壁垒"，L2 决定"业务能不能搬上线"，L3 决定"效率能不能翻倍"，L4 决定"人愿不愿意天天用"。任何一层缺失，产品都不成立——但建设顺序必须是 **L1 → L2 → L3 → L4**（先有数据地基，再有业务上线，再叠加智能体，最后做角色视图）。

### 4.2 L1 数据底座：壁垒是怎么建起来的

**（1）三类数据源**

| 数据域 | 数据内容 | 来源 | 获取策略 | 归属 |
|---|---|---|---|---|
| **① 全球B端客户大数据** | 全球海关交易数据、全球企业库（公司/联系人）、采购商与供应商数据、贸易趋势 | UN Comtrade、商业数据商 | 三阶段：免费API → 商业授权 → 批量采购自建 | 公域（可购买） |
| **② 互联网/社媒大数据** | 搜索指数、搜索量、热搜词、趋势词、社媒热词与话题、内容趋势、舆情 | Google Trends、TikTok Creative Center、社媒平台API | API接入 + 定期采集 | 公域（可购买） |
| **③ 企业内部营销服大数据** | 客户档案、跟进记录、线索、商机、订单、OTD交付、售后记录、内容与社媒运营数据 | **系统内生**（人工操作 + 智能体执行沉淀） | 随业务发生即时沉淀 | 私域（独占） |

**核心判断**：①② 花钱就能买到，是入场券；③ 只能靠自己攒，是护城河。

**（2）企业实体中心——壁垒的枢纽**

三类数据之所以过去各说各话，是因为缺少统一归集点。企业实体中心以"企业"为统一实体，把三方的公司记录通过统一实体ID挂接，形成**一企一档**：

```
全球企业库的公司  ──┐
海关数据的采购商  ──┼──→ 【企业实体中心】──→ 一企一档（企业全息档案）
社媒访客的公司    ──┤     统一实体ID
我的客户档案      ──┘     + 多源映射与消歧
```

挂接后，一条记录同时具备：**采购能力 + 触达方式 + 在谈商机 + 历史订单 + 售后记录**。

**（3）企业实体消歧规则（已定稿）**

| 优先级 | 匹配维度 | 规则 | 判定强度 |
|---|---|---|---|
| 1 | **企业域名** | 规范化后（去 www、去协议）完全一致即判定同一企业 | 强匹配，自动归并 |
| 2 | **企业名称规范化** | 去法律后缀（Ltd/LLC/GmbH/Co.,Ltd等）、去标点空格、大小写归一、多语言译名映射后完全一致 | 强匹配，自动归并 |
| 3 | **地址 + 行业** | 国家+城市一致 且 行业一致 且 名称相似度 ≥ 0.85 | 弱匹配，**进入人工确认队列** |
| — | 兜底 | 以上均不命中 | 建为新实体，保留来源标记 |

归并动作可逆，人工可在"实体合并/拆分"界面纠错，纠错结果回写规则库提升后续准确率。

**（4）数据资产四层**

| 层级 | 内容 | 作用 |
|---|---|---|
| 接入层 | 三类数据源统一注册、调度、增量同步、质量监控 | 数据进得来、进得准 |
| 明细层 | 企业实体、客户、商品、订单、跟进、内容等明细 | 业务事实的唯一记录 |
| **资产层** | **企业图谱**（企业-联系人-行业-区域）、**产品图谱**（品类-HS-应用场景）、**标签体系**、**指标体系** | 可复用资产（壁垒核心） |
| 应用层 | 画像、评分、推荐、预警、报告所需的数据服务 | 供智能体与业务界面调用 |

**（5）数据飞轮**

```
外部数据（入场券）→ 提供目标客户与市场机会
        ↓
客户开发 / 营销触达 → 成交与交付
        ↓
每次互动沉淀为内部数据（私域独占）
        ↓
数据越厚 → AI评分/推荐/预警越准
        ↓
获客效率越高 → 更多互动 → 数据更厚
        ↓
客户迁移成本极高（数据+资产+习惯都在平台上）= 壁垒成型
```

**（6）外部数据采购节奏（已定稿）**

| 阶段 | 策略 | 目标 |
|---|---|---|
| 一期 | **以免费源为主 + 小范围商业数据验证价值**（限定 1~2 个重点行业/市场采购样本数据） | 验证"外部数据 → 线索转化"的实际价值，避免重金投入无回报 |
| 二期 | 依据一期验证结论放量采购（海关数据 + 企业库按行业/区域批量授权） | 规模化获客能力 |
| 三期 | 自建数据资产（爬取/合作/沉淀），降低对外部供应商依赖 | 数据源成本壁垒 |

| **客户开发智能体** | 7×24 找客户、触达客户、初筛线索 | 客户销售服务总监 |

| 智能体 | 做 | 不做（硬约束，越界转人工） |

| 客户开发 | 批量检索筛选目标客户、首触与多轮自动跟进、A/B测试、意向度评分、名单维护 | 报价与价格承诺、合同条款谈判、付款条件、关键客户关系决策 |
| 市场分析 | 数据监测、机会扫描、容量评估、竞品监测、报告生成、异动预警 | 产品开发最终决策、定价决策、营销预算分配 |
| 内容创意 | 选题策划、多模态内容生成、多语言本地化、品牌一致性校验、变体批量生产 | 内容最终发布审批、品牌调性最终裁定、涉政敏感内容 |
| 社媒运营 | 排期发布、常规互动回复、数据监测、询盘转线索、账号健康预警 | 账号授权/资质操作、涉政与舆情敏感回复、危机公关 |
| 营销客服 | 即时接待、标准答疑、记录生成、工单创建、跟进提醒 | 价格最终承诺、合同条款、赔偿决策、投诉升级 |

**（3）智能体协作链路**

```
                   ┌─────────────────────────┐
                   │    经营分析智能体         │
                   │  横向监测·归因·效能评估    │
                   └────────────┬────────────┘
                                │ 反馈与调度建议
  ┌────────────┐   机会    ┌────┴────────┐   内容    ┌────────────┐
  │ 市场分析   │ ────────→ │ 客户开发     │ ←─────── │ 内容创意   │
  │ 找市场机会 │           │ 找客户触达    │           │ 产内容多语言│
  └────────────┘           └──────┬──────┘           └──────┬─────┘
                                  │ 线索                    │ 内容
                                  ▼                        ▼
                         ┌─────────────────┐      ┌─────────────┐
                         │  营销客服智能体   │ ←────│ 社媒运营智能体│
                         │ 接待·跟进·售后   │ 线索  │ 发布·互动·监测│
                         └─────────────────┘      └─────────────┘
                                  │ 记录/工单
                                  ▼
            客户中心 / 商机中心 / 线索中心 / 售后服务（人工可随时接管）
                                  │ 数据沉淀
                                  ▼
                      数据底座（企业实体中心）
```

**协作三原则**：①**产出即入库**（智能体产出直接写业务表，界面可见可接管）；②**不越界**（"不做清单"是硬约束）；③**效能可评**（运行留痕，经营分析智能体定期出效能报告）。

**（4）智能体自主度分级（已定稿）**

| 等级 | 名称 | 行为定义 | 适用范围 |
|---|---|---|---|
| **A0** | 建议型 | 只输出建议，人确认后才执行 | 定价建议、市场进入判断、产品开发建议、策略调整 |
| **A1** | 草稿型 | 自动生成草稿，人审后生效/发出 | **所有对外内容**（社媒帖子、开发信、营销邮件）、报价相关沟通 |
| **A2** | 执行+事后审 | 自动执行，写入业务表并在界面高亮提示，人可修改撤回 | 线索登记与评分、跟进记录生成、内容排期、数据补全、标签打标 |
| **A3** | 全自动 | 自主执行，仅在异常时通知人 | 数据采集与同步、监测与预警、报告生成、指标计算、账号健康巡检 |

**定级铁律**：**对外内容与对外触达 = 必须人审（不高于 A1）；内部记录与内部计算 = 可全自动（A2/A3）**。涉及价格、合同、赔偿、投诉的动作一律 A0，不得自动执行。

## 五、产品整体策略

### 5.1 数据策略：先把数据变成资产

| 策略 | 内容 |
|---|---|
| **先内部后外部** | 一期优先打通内部数据沉淀（客户/订单/服务/内容），外部数据先小范围验证——因为内部数据是不可复制的，外部数据随时能买 |
| **一企一档** | 所有涉及"企业"的业务对象统一挂接企业实体中心，禁止各模块自建企业表 |
| **即时沉淀** | 人工操作与智能体执行同样即时入湖，不做"事后补录"式统计 |
| **资产化而非表格化** | 沉淀的不是孤立表，而是企业图谱/产品图谱/标签/指标四类可复用资产 |
| **数据即壁垒的度量** | 用"客户档案厚度（平均字段填充率+互动记录数）"作为产品成功的核心指标之一 |

### 5.2 人机融合策略：双通道原则

**每一项业务能力都同时具备两条通道，操作同一份数据、遵守同一套规则：**

| 通道 | 形态 | 适用场景 |
|---|---|---|
| **人工通道** | 界面直达操作（列表/表单/看板） | 关键决策、异常处理、需要经验判断、首次配置 |
| **智能体通道** | 智能体自动执行，结果回流同一数据 | 高重复、高计算密度、7×24、多语言场景 |

**三条铁律**：
1. **入口铁律**：人工功能必须在一级菜单可达（≤2次点击），**禁止只存在于智能体对话流中**
2. **接管铁律**：智能体执行中的任何任务，人可随时暂停/接管/修改，上下文无损交接
3. **同源铁律**：人机操作写同一张表、走同一套校验，**不允许智能体有"影子数据"**

**人机分工的判断标准是"错误代价"，不是"任务难易"**：错误可逆、代价低 → 可交给 AI 高自主；错误不可逆、代价高（价格承诺、合同条款、租户数据越权） → 必须人审。


### 5.3 智能体策略：能力演进与成效管理

| 策略 | 内容 |
|---|---|
| **边界优先于能力** | 先定义"不做什么"，再定义"做什么"——避免越界造成商业风险 |
| **自主度分级落地** | 按 A0~A3 四级配置每个动作的自主度，默认从严，效果稳定后逐级放开 |
| **效能可量化** | 每个智能体输出：任务量、采纳率、人工介入率、节省工时、成本消耗，由经营分析智能体汇总 |
| **能力演进节奏** | 一期做"能用"（线索/内容/接待/报告），二期做"好用"（评分优化/归因深入/主动建议），三期做"自主"（跨智能体协同优化） |
| **不替代判断** | 智能体输出定位为"建议"与"草稿"，决策权始终在人 |

### 5.4 交付策略：分批可控

| 批次 | 定位 | 内容重点 | 判定标准 |
|---|---|---|---|
| **P0-A 骨架批** | **先让业务跑起来、产生数据** | **客户中心 + 商机中心全量（客户域三中心中的两个）** + 商品主数据与素材 + 订单与OTD + 售后记录与工单 + 内容生成分发 + 社媒账号 + 数据底座核心（接入/企业实体中心/指标体系）+ 六智能体基础版 + **2个优先工作台** | 业务能在系统里完成一天的工作，数据开始沉淀 |
| **P0-B 增强批** | **数据变厚后增强** | **客户标签与价值分层**、商品分类属性、单证回款、质量反馈、数据质量监控、标签体系、智能体进阶能力 + 其余3个工作台 | AI 产出采纳率稳定，数据资产显著增厚 |
| P2 | 体验与效率补充 | **线索中心全量（线索池 / 线索评分 / 线索转化）**、报价管理、渠道对比、竞品监测、内容效果分析、知识萃取等 | — |

> **线索中心为何后置 P2**：一期先把「一企一档 + 商机推进」跑通——客户主档与商机阶段是业务每天都要用的主干；线索池是**入口**能力，其价值依赖客户主档的查重与归并规则先稳定（否则线索转化会产生大量重复客户）。线索中心整体进 **P2（二期）**，与客户域三中心「菜单先齐、能力分批」的节奏一致：**菜单项在一期即出现在侧边栏并标注「二期」**，避免二期上线时用户找不到入口。

**角色工作台优先级（已定稿）**：先做 **客户销售服务总监工作台 + CEO 工作台**——前者是业务主战场（线索/跟进/商机/售后），后者是决策主入口（经营/风险/资产）。两个工作台跑通后，其余三个按"产品开发总监 → 内容创意总监 → 渠道运营总监"顺序补齐。

**OTD 节点定义（已定稿）**：系统提供**默认节点模板**（订单确认 / 排产 / 生产完工 / 出运 / 报关 / 到港 / 签收），**企业可配置**——允许增删节点、改节点名、设标准工期与预警提前量，适配贸易型与生产型企业的差异。

### 5.5 壁垒与商业化策略

| 壁垒层次 | 内容 | 强度 |
|---|---|---|
| 数据源获取 | 外部数据采购能力 | 中（可复制） |
| **企业实体资产** | 一企一档越用越厚 | **强** |
| **内部数据沉淀** | 客户用得越久越难迁移 | **强（随时间递增）** |
| 智能体效果 | 依赖数据厚度，是壁垒的结果而非原因 | 中 |
| 使用习惯 | 角色工作台成为每日入口 | 中 |

**商业化路径**：内部自用跑通（验证闭环 + 积累数据）→ 同行业标杆客户验证（打磨行业模板）→ 行业化输出（把沉淀的企业图谱与行业模板变成可复制的加速度）。

| 层级 | 交互约定 |
|---|---|

### 6.2 双通道交互：同一件事的两条路径

**以"跟进一个客户"为例**：

| 步骤 | 人工通道 | 智能体通道 | 数据归属 |
|---|---|---|---|
| 1 发现 | 打开客户中心 → 今日待跟进列表 | 营销客服智能体识别客户回复，主动提醒 | 同一客户表 |
| 2 了解 | 打开客户 360 视图看历史沟通与商机 | 智能体自动汇总"该客户近 3 次互动 + 当前商机阶段" | 同一档案 |
| 3 行动 | 手写跟进记录 / 发邮件 | 智能体生成跟进记录草稿 + 开发信草稿 | 同一记录表 |
| 4 确认 | 人工直接提交 | 人工审核草稿 → 通过或修改 | — |
| 5 沉淀 | 记录写入客户档案 | 记录写入客户档案 | 同一档案 |

**关键交互约定**：
- **可切换**：任何智能体执行中的任务，界面显示"接管"按钮，点击后转入人工操作流，上下文完整保留
- **可追溯**：智能体产出的每一条记录都带"来源：智能体名称 + 时间"，人工修改后保留修改痕迹
- **不阻断**：智能体未完成的任务不阻塞人工操作，两条通道并行不互斥

### 6.3 角色工作台交互

**默认页即当日工作**，五个工作台的默认内容各不相同：

| 工作台 | 默认首屏 | 关键交互 |
|---|---|---|
| **CEO** | 经营总览（营收/利润/增长）+ 风险预警 + 客户资产 + AI人效 | 点指标卡下钻到明细；问句直接取数 |
| **产品开发总监** | 高潜力机会清单 + 商品数据完整度 + 售后质量反馈 | 从机会卡一键"发起选品评估"；从质量反馈跳转改品建议 |
| **渠道运营总监** | 订单量结构 + OTD准时率与异常单 + 渠道产出排行 | 点异常单看卡点环节；从渠道排行下钻明细 |
| **内容创意总监** | 内容日历 + 待审内容 + 效果排行 + 账号健康 | 待审内容直接审核；效果差的条目一键看归因 |
| **客户销售服务总监** | 线索池 + 今日待跟进 + 商机漏斗 + 售后工单 | 线索一键分配/认领；商机卡拖拽推进阶段 |

**统一交互约定**：
- 每个工作台的卡片都可点击下钻到对应业务模块的明细页（**工作台是入口不是孤岛**）
- 卡片右上角为"三日内变化"（上升/下降），而不是静态数值
- 待办类卡片支持"直接处理"（如审核、分配、关闭），无需跳转

### 6.4 业务对象详情页：统一范式

客户 / 商机 / 线索 / 商品 / 订单 / 服务**六类**核心业务的详情页采用**同一套版式**，降低学习成本：

```
┌────────────────────────────────────────────────────────────┐
│  对象标题（名称/编号）  ｜ 状态标签  ｜ 关键操作按钮（编辑/新增/更多）│
├────────────────────┬───────────────────────────────────────┤
│                    │  Tab：概览 ｜ 记录/明细 ｜ 关联 ｜ 分析    │
│  左侧信息栏         │  ┌───────────────────────────────────┐ │
│  （核心属性 + 标签） │  │                                   │ │
│                    │  │        右侧内容区                  │ │
│  智能体建议卡        │  │  · 概览：关键指标卡 + 时间线         │ │
│  （如有，置顶显示）   │  │  · 明细：表格（可编辑/可筛选）       │ │
│                    │  │  · 关联：上下游对象（订单↔客户）      │ │
│                    │  │  · 分析：该对象的趋势与对比          │ │
│                    │  └───────────────────────────────────┘ │
└────────────────────┴───────────────────────────────────────┘
```

**六类对象的 Tab 约定**：

| 对象 | 概览 | 明细 | 关联 | 分析 |
|---|---|---|---|---|
| **线索** | 关键指标 + 核验状态 | 联系信息 / 触达记录 | **转化去向（客户）** | 来源质量 / 转化率 |
| **客户** | 关键指标 + 互动时间线 | 跟进记录 / **商机（一跳可达）** / 订单 | 联系人 / 同集团企业 | 采购趋势 / 健康度 |
| **商机** | 关键指标 + 阶段停留条 | 跟进记录 / BANT / 竞品 | **归属客户 / 来源线索 / 关联订单** | 阶段停留 / 赢输归因 |
| 商品 | 关键指标 + 素材预览 | 规格明细 / 多语言信息 | 关联素材 / 引用该商品的内容 | 搜索热度 / 询盘量 |
| 订单 | 关键指标 + OTD节点条 | 商品行 / 单证 / 回款 | 客户 / 物流 | 利润分析 / 周期对比 |
| 服务 | 关键指标 + 处理时间线 | 处理过程 / 工单流转 | 客户 / 关联订单 / 关联商品 | 问题分布 / 满意度 |

> **客户域三对象详情页的互跳约定**：线索详情页的「转化去向」直接跳客户 360；客户 360 的商机列表点击跳商机详情；商机详情页的「归属客户」跳回客户 360。跨菜单跳转**不做新开浏览器标签**，保持单页应用内的上下文连续；且**三者的权限各自独立判定**——能看到商机不等于能看到客户全部信息（字段级权限在三处分别生效）。

### 6.5 智能体协作交互

| 环节 | 交互设计 |
|---|---|
| **任务下发** | 在工作台或对象页用自然语言下任务（"给这批线索写开发信"），或由智能体按计划自动执行 |
| **运行可见** | 底部状态栏与智能体中心显示运行中任务；对象页显示"该对象有智能体任务进行中" |
| **产出抵达** | 产出落到对应业务表并在顶部生成"待处理"提示；对外内容类产出进入"待审队列" |
| **人工接管** | 任务卡上提供「接管 / 暂停 / 终止」按钮；接管后人工操作流自动载入已有上下文 |
| **审核发布** | 内容类产出进入待审列表，支持"通过 / 修改后通过 / 退回重做"，审核意见回写智能体 |
| **异常升级** | 自主度不足、连续失败、触及"不做清单"时，任务状态变更为「需人工处理」并高亮 |
| **效能回看** | 智能体中心展示每个智能体的产出量、采纳率、人工介入率、节省工时 |

### 6.6 全局交互规范

| 规范 | 要求 |
|---|---|
| **入口深度** | 任何基础运营功能 ≤2 次点击可达；一级菜单对象化命名，不使用职能概念 |
| **列表页规范** | 左侧筛选 + 顶部搜索 + 批量操作 + 列自定义 + 导出；空态给出"下一步怎么做"的引导 |
| **表单规范** | 最少字段可保存（先存下来，再补全）；AI 自动补全建议以浅色提示呈现，一键采纳 |
| **反馈规范** | 所有异步操作有进度反馈；智能体任务显示进度与预计耗时；失败给出原因与下一步 |
| **异常规范** | 连接异常（隧道/数据同步）时，顶部横幅提示并联系环境自愈；关键数据缺失时提示补录入口而非报错 |
| **权限规范** | 无权限功能不展示（而非禁用后报错）；敏感操作二次确认并记录审计日志 |
| **空数据规范** | 新租户首次进入时，用引导式任务（导入客户/建商品/连账号）代替空白页 |
| **多语言规范** | 界面中英双语可切换；数字与金额按客户所在地格式呈现；日期时区自动适配 |
