# ADR-0003 智能体运行时置于后端仓库内独立进程

| 项 | 内容 |
|---|---|
| 状态 | 已采纳（Accepted） |
| 日期 | 2026-09-11 |
| 决策人 | 产品与架构负责人 |
| 影响范围 | `lingxi-server`（`lingxi-agent-runtime` / `lingxi-data-jobs`）· `lingxi-ops`（部署脚本与 systemd） |

## 背景

灵犀系统含 L3 智能体层（六大智能体）与 L1 数据底座（采集 / 清洗 / 实体消歧 / 指标计算）。
这些负载与业务单体在**运行时特性**上差异明显：

| 维度 | 业务单体 | 智能体 / 数据任务 |
|---|---|---|
| 调用耗时 | 毫秒~秒 | 秒~分钟（LLM 调用、批量采集） |
| 失败模式 | 请求级失败 | 长任务中断、需断点续跑 |
| 资源占用 | 平稳 | 峰值高、突发 |
| 发布节奏 | 随业务发版 | 随模型 / 数据源变化 |

需要决定：它们是否与业务单体同进程？是否独立仓库？是否换语言？

## 决策

**不独立仓库、不换语言，但在同一仓库内作为独立部署进程。**

- `lingxi-agent-runtime`：L3 运行时（编排 / 工具网关 / 护栏 / 边界拦截 / Token 计量），独立 Spring Boot 进程
- `lingxi-data-jobs`：数据任务进程（采集 / 清洗 / 消歧 / 指标计算），独立 Spring Boot 进程
- 三者（含业务单体）同属 `lingxi-server` 一个 Maven 仓库，共享 BOM、Starter 与 CI
- 通过 systemd 各自拉起，独立重启；接口相互通过 HTTP（内网 `127.0.0.1`）与事件（Outbox）交互
- 【明确】二者**不计入** 14 个单体模块的计数口径

## 理由

1. **进程隔离买到了最关键的收益**：LLM 调用超时、批量采集把内存打满，都只影响自己的进程，业务接口不会被拖垮。这是分离的根本目的。
2. **不独立仓库**：AI Coding 需要跨边界改代码（新场景要同时改运行时与业务模块的契约）。拆成两个仓库会让一个改动变成两个 PR、两套 CI、两次评审，反而降低自动化流水线的可靠性。
3. **不换语言**：把 Python 排除在业务链路外是本项目已确立的技术原则。多语言栈意味着两套依赖治理、两套构建、两套类型体系——对 AI Coding 是灾难。数据任务用 Java + 定时/批处理框架足以承载一期规模。
4. **共享 BOM 与 Starter**：三者用同一套统一响应体、TraceId、租户上下文、审计填充。若拆库，这些公共能力要么重复实现，要么抽成外部包并引入版本协调问题。
5. **智能体与人工同源**：运行时执行的写操作必须落在与人工相同的 Application Service 上（双通道同源铁律）。同仓同 BOM 使「同一 service 被两个进程调用」在编译期就可校验。

## 被否方案

| 方案 | 否决理由 |
|---|---|
| 智能体运行时独立仓库 | 契约变更需跨仓 PR，自动化流水线需处理多仓依赖顺序；收益（解耦）在一期团队规模下不成立 |
| 数据任务用 Python（`lingxi-data-worker`） | 已确认排除 Python 承载业务逻辑；一期规模用 Java 足够，避免双语言治理成本 |
| 智能体与业务同进程 | LLM 调用会占用 Web 容器线程与连接；长任务（分钟级）会拖垮接口响应，且无法独立重启 |
| 智能体运行时先拆为微服务集群 | 一期无水平扩展需求；引入服务发现与配置中心，违反最小组件数原则 |

## 影响与后续约束

- 【强制】模块计数口径固定：14 个 Maven 模块 = 11 业务 + `lingxi-data` + `lingxi-platform` + `lingxi-dependencies`；`lingxi-agent-runtime` 与 `lingxi-data-jobs` 不计入
- 【强制】禁止 `/api/agent/**` 影子写接口；运行时只能调用业务模块的 Application Service
- 【强制】自主度判据唯一来源为 `AutonomyPolicyApi#resolve`，禁止调用方自行判断能否放行
- 【强制】对外内容与触达 ≤A1，价格/合同/赔偿/投诉强制 A0（数据库 CHECK 约束兜底，见 `ag_autonomy_policy`）
- 【推荐】后续若智能体负载确实需要独立扩缩容，再评估拆仓；拆仓决策须新开 ADR
- 代价：单仓 CI 需同时构建三个可执行进程，构建时间略增；已通过 Maven 模块化并行构建缓解
