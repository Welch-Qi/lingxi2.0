# 灵犀 2.0 · 字段级数据字典 · 10 智能体（L3：`ag_`·仅业务运行面）

> **版本**：V0.2 草案（待评审）｜2026-10-13｜任务：M0000-008（Wave 3 六域补全）；V0.2：**ADR-0004 同日关联裁决—`ag_task` 留灵犀域已结案**
> **前置**：公共列、来源标记列、类型口径、枚举 `E{n}`、追加型豁免见《字段级数据字典-00-公共约定.md》。
> **来源依据**：《功能清单V2.1》智能体（AG-01~06 业务面）、UW-11 接管铁律、UW-24 待审队列。
> **定位**：本域**只承载灵犀业务运行面**——智能体实例名册、任务实例、执行轨迹、待审队列、接管留痕。均为租户私域（`租户=是｜RLS=是`）；`ag_task` 即 00 §三 `source_task_id` 所指目标。
> **🔴 归口边界（硬约束）**：智能体**注册中心 / 自主度策略 / 协作总线 / 越界拦截规则 / 监控看板配置**（AG-07~09、AC-01~09）归 **元枢 `yuanshu-agent-factory`（`com.yuanshu.ac`）**，本侧**不建策略/注册表**，仅在 `ag_task`/`ag_agent_instance` 以 `autonomy_policy_ref`/`agent_reg_ref` **逻辑引用**。提示词（KC-16~19/22）归元枢。✅ **`ag_task` 业务实例归属（即 A2）已同日结案：留灵犀域**（元枢仅持注册/自主度）；`00 §三` 引用口径无需回改。自主度判据仍由 `AutonomyPolicyApi#resolve` 单一入口，不属本侧。

## 一、实例名册（`ag_agent_instance`）

### 1.1 `ag_agent_instance` · 灵犀六智能体业务实例名册
> 租户:是｜RLS:是｜来源:否｜分区:否
> 灵犀侧对 AG-01~06 六个智能体的**业务实例登记**（谁在用、开没开、绑哪些能力）；运行时注册与调度权威在元枢，此处仅业务映射。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `agent_code` | `VARCHAR(32)` | `NOT NULL` | **E77**（六智能体编码，与元枢注册中心对齐） |
| `display_name` | `JSONB` | `NOT NULL` | 实例展示名（多语言） |
| `agent_reg_ref` | `VARCHAR(128)` | | 🔴 元枢注册中心引用（`com.yuanshu.ac` 注册 ID，逻辑引用非外键） |
| `autonomy_policy_ref` | `VARCHAR(128)` | | 🔴 自主度策略引用（元枢侧策略 ID；对外内容必人审 §3.6 G4 ≤A1） |
| `enabled` | `BOOLEAN` | `NOT NULL default true` | 业务侧是否启用 |
| `scope_json` | `JSONB` | | 授权业务范围（可操作的数据域/字段，快照自元枢策略） |
| `owner_user_id` | `BIGINT` | | 业务责任人 |

索引：`UNIQUE(tenant_id, agent_code) WHERE is_deleted=0`、`(enabled)`。

## 二、任务实例（`ag_task`）

### 2.1 `ag_task` · 智能体任务〔P0-A〕
> 租户:是｜RLS:是｜来源:是（智能体自身即来源）｜分区:否
> **即 00 §三 `source_task_id` 所指业务任务实例**。承载"某智能体对某业务对象做的一件事"的状态机与产出。自主度/调度策略在元枢，本表存任务运行结果与逻辑引用。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `task_no` | `VARCHAR(64)` | `NOT NULL` | 任务号（业务键，`AT-20261012-0001`） |
| `agent_code` | `VARCHAR(32)` | `NOT NULL` | **E77** 执行智能体 → `ag_agent_instance` |
| `biz_obj_type` | `VARCHAR(32)` | `NOT NULL` | 业务对象类型（线索/内容/邮件/报告/会话…） |
| `biz_obj_id` | `BIGINT` | | 业务对象 ID（逻辑引用对应域表） |
| `intent` | `JSONB` | | 任务目标/指令（多语言） |
| `initiator_user_id` | `BIGINT` | | 发起用户（自动触发可空） |
| `status` | `VARCHAR(16)` | `NOT NULL default 'CREATED'` | **E76** 任务状态机 |
| `autonomy_level` | `VARCHAR(8)` | | 本次运行自主度档（快照自元枢策略，展示用，权威在元枢） |
| `result_json` | `JSONB` | | 产出结果（写回业务对象前的结构化产出） |
| `needs_human_reason` | `TEXT` | | `NEEDS_HUMAN` 时的人工介入原因 |
| `started_at` | `TIMESTAMPTZ` | | 开始执行 |
| `finished_at` | `TIMESTAMPTZ` | | 结束（完成/失败/接管） |
| `duration_ms` | `INTEGER` | | 耗时（`mv_ana_agent_efficiency` 聚合源） |
| `cost_min` | `BIGINT` | | LLM/算力成本（最小单位，配额计量） |
| `currency` | `CHAR(3)` | | ISO-4217 |

索引：`UNIQUE(tenant_id, task_no) WHERE is_deleted=0`、`(agent_code, status)`、`(biz_obj_type, biz_obj_id)`、`(initiator_user_id, status)`、`(status, finished_at)`。
> **不加物理外键**（A1 边界）：`biz_obj_id`/`source_task_id` 均为逻辑引用，跨模块靠应用 + 事件保证。

## 四、待审队列（`ag_pending_review`）

### 4.1 `ag_pending_review` · 待人工审核队列〔P0-A〕
> 租户:是｜RLS:是｜来源:是｜分区:否　（UW-24）
> 智能体产出的**对外内容 / 开发信**必经人审方可发布（§3.6 G4）。本表是跨域待审的**统一入口**，引用 `mkg_content`/`svc_session` 等，不复制被审对象内容。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `review_no` | `VARCHAR(64)` | `NOT NULL` | 待审单号 |
| `task_id` | `BIGINT` | | 来源任务 → `ag_task.id` |
| `reviewee_type` | `VARCHAR(32)` | `NOT NULL` | 被审对象类型（`mkg_content`/`mkg_email_campaign`/`svc_session`…） |
| `reviewee_id` | `BIGINT` | `NOT NULL` | 被审对象 ID（逻辑引用；营销内容亦可直接按其 `status=REVIEW` 过滤源表，见 07） |
| `review_type` | `VARCHAR(16)` | `NOT NULL` | 内容合规 / 开发信 / 报价 / 话术（登记） |
| `risk_level` | `VARCHAR(8)` | | **E30** 审核优先级 |
| `status` | `VARCHAR(16)` | `NOT NULL default 'PENDING'` | 待审 / 通过 / 驳回（复用 **E18** `review_status` 值集语义；本域用 `PENDING/APPROVED/REJECTED`） |
| `assignee_user_id` | `BIGINT` | | 审核人 |
| `opinion` | `TEXT` | | 审核意见（驳回附原因） |
| `reviewed_at` | `TIMESTAMPTZ` | | 审核时刻 |

索引：`UNIQUE(tenant_id, review_no) WHERE is_deleted=0`、`(status, risk_level)`、`(reviewee_type, reviewee_id)`、`(assignee_user_id, status)`。

## 五、接管留痕（`ag_takeover`）

### 5.1 `ag_takeover` · 人工接管留痕〔P0-A〕
> 租户:是｜RLS:是｜来源:是｜分区:否　（UW-11 接管铁律）
> "随时可暂停 / 接管 / 终止 / 退回"是人机协同铁律的**审计落点**。每次干预一行，保留接管时上下文快照。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `task_id` | `BIGINT` | `NOT NULL` | → `ag_task.id` |
| `action` | `VARCHAR(16)` | `NOT NULL` | **E78**（暂停/接管/终止/退回） |
| `operator_user_id` | `BIGINT` | `NOT NULL` | 干预人 → `sys_user.id` |
| `reason` | `TEXT` | | 干预原因 |
| `context_json` | `JSONB` | | 接管时刻上下文快照（智能体状态/待决内容） |
| `took_over_at` | `TIMESTAMPTZ` | `NOT NULL default now()` | 干预时刻 |

索引：`(task_id, took_over_at)`、`(operator_user_id, action)`。
> `ag_task.status` 相应迁移：`RUNNING`→`PAUSED`（PAUSE）/`TAKEN_OVER`（TAKE_OVER）/`FAILED`（TERMINATE）/`NEEDS_HUMAN`（退回等待人工）。

## 七、跨域与归口约束

- **被 00 §三回指**：所有 `source_task_id` 逻辑指向 `ag_task.id`（07/08/09 智能体产出均经此溯源）。
- **业务对象引用**：`ag_task.biz_obj_id`/`ag_pending_review.reviewee_id` 逻辑引用 `mkg_content`/`svc_session`/`cus_lead` 等；不建物理外键。
- **🔴 归口元枢（不建表）**：`agent_reg_ref`（注册）、`autonomy_policy_ref`（自主度）、越界拦截规则（`ag_task_trace.intercept_hit` 仅存命中事实）、技能/MCP/模型配置、协作总线、监控看板配置 → 元枢 `com.yuanshu.ac`；本侧仅逻辑引用与运行结果快照。
- **审计**：接管/待审/拦截为合规审计重点，写路径必配 `sys_audit_log`；自主度红线（无人值守对外动作）标 🔴 待 ADR-0004。
- **事件命名**：灵犀侧一律 `lx.ag.*`（硬约束 3）；元枢运行时事件 `ys.*` 不在本文件登记。

## 八、待决策项（留人工裁决）

1. **✅ `ag_task` 归属**（已结案 · 2026-10-13 同日裁决）：业务任务实例**留灵犀域**（因 `source_task_id`/前端待审/接管消费在此）；元枢 `com.yuanshu.ac` 仅持有注册与自主度策略，不为任务实例建表。`00 §三` 引用口径无需回改；事件继续以 `lx.ag.task.*` 命名。
2. **`ag_pending_review.status` 与 E18 复用**：待审值集与 `dt_entity_review_queue`（E18 `PENDING/APPROVED/REJECTED`）语义一致，本草案复用 E18；是否需独立 E 码区分"人审内容"场景，待确认。
3. **`ag_task_trace` 留存与合规**：轨迹含 LLM 输入输出，可能涉敏感/体积大——留存周期、脱敏与冷存策略待 05-security 对齐。
