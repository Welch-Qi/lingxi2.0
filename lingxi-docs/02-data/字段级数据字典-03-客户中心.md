# 灵犀 2.0 · 字段级数据字典 · 03 客户中心（L2：`cus_`）

> **版本**：V0.2（2026-09-13 评审回写）
> **前置**：公共列、来源标记列、类型口径、枚举 `E{n}` 见《字段级数据字典-00-公共约定.md》。
> **定位**：客户中心为**租户私域**，所有表 `租户=是｜RLS=是`。企业基础信息不冗余，仅以 `entity_id` 引用 L1 公域实体 + 存最少展示快照（主数据引用规则）。
> **双通道**：线索/跟进/商机可由智能体写入 → 均含来源标记列（`来源=是`）。

---

## 一、客户与联系人

### 1.1 `cus_customer` · 客户主档

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `biz_code` | `VARCHAR(64)` | `NOT NULL` | 客户编号 |
| `entity_id` | `BIGINT` | `NOT NULL` | → `dt_entity_company.id`（企业权威档案） |

| `industry_code` | `VARCHAR(64)` | | |

| `source_channel` | `VARCHAR(32)` | | 来源渠道：展会/官网/情报/智能体… |
| `owner_user_id` | `BIGINT` | `NOT NULL` | 归属人 → 数据权限维度 `OWNER` |
| `region_code` | `VARCHAR(32)` | | 数据权限维度 `REGION` |
| `market_code` | `VARCHAR(32)` | | 数据权限维度 `MARKET` |
| `stage` | `VARCHAR(24)` | `NOT NULL` | 客户生命周期阶段 |

索引：`UNIQUE(tenant_id, biz_code) WHERE is_deleted=0`、`UNIQUE(tenant_id, entity_id) WHERE is_deleted=0`、`(owner_user_id)`、`(tier, stage)`、`(tenant_id, is_in_public_pool, owner_user_id)`（P1-4：公海领取/退回扫描，已替低区分度单列索引）。
> 一个租户对同一企业实体仅一条客户档案（`entity_id` 唯一），公域实体升级自动同步至各租户引用。

## 四、客户标签与健康度（`[B]`）

### 4.1 `cus_tag_relation` · （已收敛）
> **本表不落地**。客户/线索标签统一由 L1 `dt_tag_relation`（`target_type=CUSTOMER/LEAD`）承载，避免双份真相（见 02 §4.3）。保留编号占位以对齐概念清单。

### 4.2 `cus_health_score` · 客户健康分 `[B]`
> 来源:否（系统计算，派生）｜分区:否（仅存最新，历史走分析层）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `customer_id` | `BIGINT` | `NOT NULL` | |
| `score` | `SMALLINT` | `NOT NULL` | 0-100 |
| `risk_level` | `VARCHAR(16)` | `NOT NULL` | E30 |
| `dimension_json` | `JSONB` | | 各维度分值明细 |
| `model_version` | `VARCHAR(32)` | | 计算模型版本（口径可追溯） |
| `calc_at` | `TIMESTAMPTZ` | `NOT NULL` | 最近计算时间 |

> 健康分是**派生可重建数据**（见总览§七），非事实来源；模型/口径变更可整表重算。
