## 三、排期、分发与营销日历（`mkg_schedule` / `mkg_distribution` / `v_mkg_calendar`）

### 3.1 `mkg_schedule` · 内容排期
> 来源:否（人工排期动作）｜分区:否
> 据 `calendar-data.ts` `ScheduleItem`。**第一等材料是时间与渠道**：跨时区运营，故每条记「当地日期 + 当地时刻 + IANA 时区」三件套，不用浏览器本地时间（否则把"当地早 9 点"排成对方下班时间）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `content_id` | `BIGINT` | `NOT NULL` | → `mkg_content.id`（前端演示 `id` 即内容号，落库换外键） |
| `channel` | `VARCHAR(16)` | `NOT NULL` | 分发渠道 **E67** |
| `account_id` | `BIGINT` | | 发布账号 → `mkg_social_account.id` |
| `local_date` | `DATE` | `NOT NULL` | 目标市场当地日期 |
| `local_time` | `VARCHAR(5)` | `NOT NULL` | 当地时刻 `HH:mm`（配合 `tz` 还原绝对时刻） |
| `tz` | `VARCHAR(64)` | `NOT NULL` | IANA 时区标识（`Europe/Berlin`…，语言中立不翻译） |
| `status` | `VARCHAR(16)` | `NOT NULL default 'SCHEDULED'` | **E65**（待审/已排/发布中/已发/改期） |
| `langs` | `JSONB` | | 发布语种数组 |
| `owner_user_id` | `BIGINT` | `NOT NULL` | 负责人 |
| `conflict_flag` | `BOOLEAN` | `NOT NULL default false` | 冲突检测命中（OP-MKT-11） |

索引：`(content_id)`、`(channel, local_date)`、`(account_id, local_date)`、`(status)`。
> 排期与分发是两件事：**排期回答"什么时候发"，分发回答"发出去了没有"**，不合并为一张换皮表（前端纪律）。

### 3.3 `v_mkg_calendar` · 营销日历（派生视图）〔OP-MKT-08/11〕
> 只读派生｜不落事实表
> 据 `mkg-calendar-data.ts` `MktCalItem`（662 行，营销目录最大前端文件）。**跨域聚合视图**：把散在各域"排上日历的事"归一成一条时间轴，`kind`＝`campaign`（`mkg_campaign`）/ `visit`·`meeting`（客户域 `cus_followup` 按类型分）/ `ticket`（服务工单 `svc_*`，待 06 建模）/ `task`（`ag_task`）。视图仅投影 + 归并，**不新增事实列**；**冲突判据 R1（同受众 × 同时段才算冲突）在查询期计算**，判据所需的 `audience`（E81）与 `conflict_group_id` 落在被聚合的源表上（本域 `mkg_campaign` 已补列，见 §1.1；他域条目按归属实体取值，无受众语义者默认 `INTERNAL` 不参与 R1）。

| 输出列 | 来源 | 说明 |
|---|---|---|
| `kind` | 源表判别 | `campaign`/`visit`/`meeting`/`ticket`/`task`（值集登记见 §十） |
| `state` | 各源 `status` 归并 | `done`/`running`/`planned`（复用活动 E62 / 排期 E65 / 任务 E76 归并三态，**不新造枚举**） |
| `title` | 各源名称字段 | 多语言 JSONB / i18n key |
| `start_date` / `end_date` | 各源起止 | `DATE`；单日事件 `end_date` 为空 |
| `audience` | 源表 `audience` | **E81**，R1 判据维度 |
| `owner_user_id` | 各源负责人 | → `sys_user.id` |
| `conflict_group_id` | 源表 | R1 豁免组（同组互不判冲突） |

> **派生不落表**：`ConflictPair`（R1 命中对）、`OverloadDay`（单日超载）、`PrepOverdue`/`PrepItem`（筹备到期）、`ReminderNode`（提醒节点）全部查询期计算，不建表不建列；前端演示锚点 `MKG_CAL_TODAY` 是测试装置、非数据字段。视图 DDL 随迁移出，本草案只给列口径与同源约束。

## 四、社媒账号（`mkg_social_account`）

### 4.1 `mkg_social_account` · 社媒账号资产
> 来源:否｜分区:否　✅ 已结案（承 ADR-0004：本表属租户私域，凭证资产 `dt_account_asset` 同属租户私域）

| `handle` | `VARCHAR(128)` | `NOT NULL` | 账号名（`@`/主页路径，语言中立不翻译） |
| `region_code` | `VARCHAR(32)` | | 主要目标市场 |
| `owner_user_id` | `BIGINT` | | 归属人 |
| `auth_status` | `VARCHAR(16)` | `NOT NULL` | **E68**（已连/即将到期/已过期/已吊销） |
| `auth_expire_at` | `DATE` | | 授权到期日（与"今天"比较得出预警档；`daysToExpire`） |
| `account_asset_id` | `BIGINT` | | → `dt_account_asset`（02 §1.4，凭证/密钥权威在此） |
| `followers` | `INTEGER` | | 粉丝数（同步值，展示层按语言格式化） |
| `health` | `SMALLINT` | | 健康度 0-100（**派生**，发布频次不足/违规/资料缺失综合；接平台侧 `health_score`） |

> **安全红线**：不存明文 token；凭证一律经 `dt_account_asset` + `sys_file`/密钥管理引用（值敏感项见 05-security）。✅ 账号资产归属已承 ADR-0004 结案：本表与 `dt_account_asset` 均为**租户私域**（`tenant_id` + RLS），不跨租户共享；Flyway DDL 已落地（`V202610161200__mkg_init_baseline.sql`）。

### 5.2 `mkg_email_variant` · EDM A/B 主题变体
> 来源:是｜分区:否
> 据 `MailVariant`。**A/B 只比主题行、不比正文**（§2.8；B2B 场景换正文会被读成骚扰）。漏斗**按变体分开记**——聚合成一份会让 A/B 差值恒为 0（"两者持平"是假的读不出结论）。

| 字段 | 类型 | 约束 | 说明 |

| `opened` | `INTEGER` | `NOT NULL default 0` | 打开数 |
| `clicked` | `INTEGER` | `NOT NULL default 0` | 点击数 |

## 六、访客识别（`mkg_visitor_session` / `mkg_lead_capture`）

### 6.1 `mkg_visitor_session` · 网站访客会话
> 来源:是｜分区:是（按月 `last_visit_at`）
> 据 `visitor-data.ts` `VisitorSession`。**识别本身不产生价值，识别出来没人跟才是白识别**——主动作是「一键触达」。匹配不到内部对象时新建的是**线索**而非客户（客户是成交事实载体，凭一次浏览建客户会污染下游分层）。可识别率量级 30–40%，非 100%。

| `company_name_raw` | `VARCHAR(256)` | | 识别出的公司展示名 |
| `domain` | `VARCHAR(256)` | | 官网域名（语言中立标识） |
| `entity_id` | `BIGINT` | | 识别命中 → `dt_entity_company.id`（挂企业实体中心） |

## 九、跨域与归口约束

- **主数据引用**：`mkg_content.product_id`、`mkg_campaign_product.product_id` → `prd_product`（只存 ID + 快照，改名自动跟随）；`owner_user_id`/`assigned` → `sys_user`；`entity_id` → `dt_entity_company`；转线索 → `cus_lead`。
- **文件/素材**：封面/视频/二进制经 `sys_file` 预签名直传（§4.9 C10）；素材复用见 `prd_material`，内容不重复上传（OP-MKT-04）。
- **合规（不重复建）**：退订、频控、统一会话见 **06**；发信前必查 `mkg_unsubscribe` + `mkg_freq_counter` 强校验（§4.7.4）。
- **归口元枢**：内容/邮件由智能体产出，其**自主度策略、越界拦截规则**在元枢 `com.yuanshu.ac`，本侧 `source_type=AGENT` + `source_agent_code`（E77）+ `source_task_id`（→`ag_task`）标记来源，不复制策略表。
- **营销日历跨域聚合**：`v_mkg_calendar`（§3.3）只读投影 `mkg_campaign`（受众 `audience` E81 + `conflict_group_id` 承载 R1 判据）+ 客户域 `cus_followup`（visit/meeting）+ 服务工单 `svc_*`（ticket，待 06 svc 建模）+ 智能体任务 `ag_task`（task）；不新建事实表，冲突对/超载日/筹备到期/提醒节点全查询期派生。他域源实体的受众维度依赖各自域补 `audience` 列（本轮仅在营销域落列，见 §十）。
- **事件命名**：灵犀侧一律 `lx.*`（硬约束 3）；元枢治理事件 `ys.*` 不在本文件登记。

## 十、待决策项（不自行定规约，留人工裁决）

1. **`mkg_content.lang` 建模粒度**：多语言内容用「每语种一行」（本草案）还是「单行 JSONB 合并」——影响 A/B 与素材关联，建议「每语种一行」对齐前端 `lang` 单值，需确认。
2. **活动 `participants`/`gmv` 是否物化**：本草案按派生（走 `ana` 视图），若需历史留存可加 `mkg_campaign_stat_daily` 快照表，待确认。
3. **`mkg_social_account` 与 `dt_account_asset` 边界**（✅ 已结案 · 承 ADR-0004）：账号“业务档案”（本表）与“凭证资产”（L1 02 §1.4）分离，**均为租户私域**（`tenant_id` + RLS），不跨租户共享；后续 Flyway DDL 与 `verify-tenant-isolation.sh` 隔离测试归后续 Wave。
4. **日历 `kind` 值集登记**：`v_mkg_calendar.kind`（`campaign`/`visit`/`meeting`/`ticket`/`task`）是否登记为独立 E 码——本草案暂列散值（`state` 归并复用 E62/E65/E76 不新造，`audience` 已登 E81），`kind` 待产品确认后补入 00 §六。
5. **日历 `ticket`/`visit` 源依赖**：`v_mkg_calendar` 工单条目依赖 `svc_*` 工单/SLA 建模（06 当前仅骨架）；svc 域补齐前视图先支持 campaign/visit/meeting/task 四类，ticket 条目留空。visit/meeting 的 `audience` 依赖 `cus_followup` 补列（本轮未跨域改客户域）。
