# 灵犀 2.0 · 字段级数据字典 · 09 经营分析（L2：`ana_`）

> **版本**：V0.1 草案（待评审）｜2026-10-12｜任务：M0000-008（Wave 3 六域补全）
> **前置**：公共列、来源标记列、类型口径、枚举 `E{n}`、追加型豁免见《字段级数据字典-00-公共约定.md》。
> **来源依据**：《功能清单V2.1》经营分析 / 决策支持（OP-BA-01~03、DM-02/17、UW-04）。
> **定位**：分析域**指标复用**平台统一口径 `dt_metric_definition`（02 §4.1），看板/漏斗/ROI/资产/效率走**物化视图** `mv_ana_*`（可随口径重建）；仅**预警规则/预警事件/报告/取数日志**落库。落库表为租户私域（`租户=是｜RLS=是`）。
> **口径红线**：分析域不落"事实"，只落"派生结论 + 规则 + 日志"。金额一律 `BIGINT` 最小单位 + 快照 `currency`；跨币种先按 `cc_exchange_rate` 折本位币（`sys_tenant.base_currency`）。

## 一、派生物化视图（可随指标口径重建，不落事实表）

> `mv_ana_*` 按 `dt_metric_definition`（**E21** agg / `sql_template` 含 `tenant_id` 占位）口径刷新；禁止把视图结果当事实回写业务表。

### 1.1 `mv_ana_kpi_overview` · 经营总览 KPI
> 聚合 `ord_order`/`cus_opportunity`/`cus_lead`/`mkg_campaign`。输出：`tenant_id`、`period`、`gmv_min`、`order_cnt`、`new_lead_cnt`、`active_opp_cnt`、`win_rate`、`campaign_roi`（各为对应 `metric_code` 口径的物化列）。

### 1.2 `mv_ana_sales_funnel` · 销售漏斗
> ← `cus_opportunity`（**E27** 七阶段）：`tenant_id`、`stage`、`opp_cnt`、`amount_min`、`conv_rate`（阶段间转化率派生）。

### 1.3 `mv_ana_roi` · 营销 / 投放 ROI
> ← `mkg_campaign` + `mkg_email_campaign` + `mkg_distribution`：`tenant_id`、`campaign_id`、`spend_min`、`attr_gmv_min`、`leads`、`cpl_min`、`roi`（触点级归因口径）。

### 1.4 `mv_ana_customer_asset` · 客户资产盘点〔OP-BA-01〕
> ← `cus_customer` + `cus_health_score`（**E30**）+ `cus_opportunity`：`tenant_id`、`tier`（**E28** S/A/B/C/D）、`customer_type`（**E59**）、`customer_cnt`、`arpu_min`、`churn_risk_cnt`、`health_avg`。

### 1.5 `mv_ana_agent_efficiency` · 智能体效率〔OP-BA-02〕
> ← 聚合 `ag_task`（10 文件）：`tenant_id`、`agent_code`（**E77**）、`task_cnt`、`completed_cnt`、`needs_human_cnt`、`taken_over_cnt`、`avg_duration_ms`、`avg_cost_min`（成本最小单位）、`human_takeover_rate`。

## 二、预警（`ana_alert_rule` / `ana_alert`）

### 2.1 `ana_alert_rule` · 预警规则〔P0-A〕
> 租户:是｜RLS:是｜来源:否｜分区:否　（OP-BA-03）
> 五类预警各一条规则：客户流失 / 订单异常 / OTD 延期 / 营销下滑 / 商机停滞。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `biz_code` | `VARCHAR(64)` | `NOT NULL` | 规则编号 |
| `name` | `JSONB` | `NOT NULL` | 规则名（多语言） |
| `alert_type` | `VARCHAR(24)` | `NOT NULL` | **E74**（预警类型五值） |
| `metric_code` | `VARCHAR(64)` | | 依赖指标 → `dt_metric_definition.metric_code`（口径来源） |
| `threshold_json` | `JSONB` | `NOT NULL` | 阈值体（比较符/阈值/持续周期，如 `{"op":"<","value":60,"window":"7d"}`） |
| `level` | `VARCHAR(8)` | `NOT NULL default 'MEDIUM'` | 预警级别（复用 **E30** `risk_level`） |
| `notify_channels` | `JSONB` | | 推送渠道数组（站内/邮件/工作台…） |
| `is_active` | `BOOLEAN` | `NOT NULL default true` | 是否启用 |
| `owner_user_id` | `BIGINT` | | 规则负责人 |

索引：`UNIQUE(tenant_id, biz_code) WHERE is_deleted=0`、`(alert_type, is_active)`。

### 2.2 `ana_alert` · 预警事件〔P0-A〕
> 租户:是｜RLS:是｜来源:是（系统/智能体触发）｜分区:是（按月 `raised_at`）｜**追加型**（00 §一·附，不建 `updated_*`/`is_deleted`/`version`）
> 规则命中生成的预警实例；`status` 走处理闭环。**闭环需更新状态**——与"仅追加"语义冲突时，本表按**事件流 + 状态列**特例保留 `status`/`updated` 由应用显式维护（登记为待确认，见 §六）。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `rule_id` | `BIGINT` | `NOT NULL` | → `ana_alert_rule.id` |
| `alert_type` | `VARCHAR(24)` | `NOT NULL` | **E74**（冗余自规则，便于分区内直查） |
| `level` | `VARCHAR(8)` | `NOT NULL` | **E30** |
| `biz_ref_type` | `VARCHAR(32)` | | 关联对象类型（客户/订单/商机/活动…） |
| `biz_ref_id` | `BIGINT` | | 关联对象 ID（逻辑引用，不建物理外键） |
| `title` | `JSONB` | `NOT NULL` | 预警标题（多语言） |
| `detail_json` | `JSONB` | | 命中快照（触发时指标值/阈值/上下文） |
| `status` | `VARCHAR(16)` | `NOT NULL default 'NEW'` | **E75**（新/已确认/已处理/已关闭） |
| `assignee_user_id` | `BIGINT` | | 处理人 |
| `raised_at` | `TIMESTAMPTZ` | `NOT NULL` | 触发时刻（分区键） |
| `closed_at` | `TIMESTAMPTZ` | | 闭环时刻 |
| `source_type` | `VARCHAR(10)` | `NOT NULL default 'SYSTEM'` | **E1**（系统规则 / 智能体触发） |

索引：`(rule_id)`、`(status, level)`、`(biz_ref_type, biz_ref_id)`、`(assignee_user_id, status)`、`(raised_at)`。
> 事件 `lx.ana.alert.raised`（命中）/ `lx.ana.alert.closed`（闭环）；`NEW`→`ACKNOWLEDGED`→`RESOLVED`→`CLOSED`。

## 五、跨域与归口约束

- **指标口径**：所有 `mv_ana_*` 与 `ana_alert_rule.metric_code` 复用 `dt_metric_definition`（**E21**），不在分析域重定义口径。
- **上游引用**：漏斗←`cus_opportunity`（E27）；客户资产←`cus_customer`/`cus_health_score`（E28/E59/E30）；ROI←`mkg_*`（07）；OTD 延期预警←`ord_otd_node`（E35/E36）；智能体效率←`ag_task`（10）。
- **下游联动**：`ana_alert` 经 `sys_message`/`v_wb_todo`（12）进工作台待办；`mv_rw_kpi`（12）复用本域物化视图。
- **归口元枢**：`ana_report`/`ana_nlq_log` 正文向量化、NLQ 语义解析模型由元枢 `com.yuanshu.sem`/`com.yuanshu.ac` 提供，本侧仅存结构化结果与快照。
- **安全红线**：`ana_nlq_log.parsed_params_json` 落 LLM 解析结果，执行仍走受控模板 + 只读账号 + 行数/超时上限（P1-11，同 02 §4.1）；LLM 不得直出 SQL。
- **事件命名**：灵犀侧一律 `lx.*`（硬约束 3）。

## 六、待决策项（留人工裁决）

1. **`ana_alert` 追加型 vs 闭环更新的冲突**：本草案将其列入 00 §一·附追加型，但预警需状态闭环（`status`/`closed_at`/`assignee` 会变）——严格"仅追加"不成立。建议**移出追加型**或改为"事件流表 + 独立处理表"拆分，待确认（影响 00 §一·附清单）。
2. **`mv_ana_*` 刷新策略**：全量/增量、刷新频率（实时/日结）与物化视图并发刷新锁，待与调度（元枢）对齐。
3. **`ana_report` 与 `intel_opportunity_report` 边界**：二者均报告快照型，是否合并为统一 `report` 域按 `report_type` 区分，待产品确认。
