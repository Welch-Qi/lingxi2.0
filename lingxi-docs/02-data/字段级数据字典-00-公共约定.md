## 一、公共列（所有租户业务表默认自带，禁止手工赋值）

由 `yuanshu-starter-mybatis` 的拦截器自动填充（命名承规约 §2.6 元枢底座 Starter 拆分）；`domain` 层不感知。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | `PK` | 雪花 ID，全库唯一；禁止自增 / UUID |
| `tenant_id` | `BIGINT` | `NOT NULL` | 租户 ID；由租户拦截器注入；**白名单表无此列**（见 §2） |
| `created_by` | `BIGINT` | `NOT NULL` | 创建人 `sys_user.id`；系统写入填 `0` |
| `created_at` | `TIMESTAMPTZ` | `NOT NULL default now()` | UTC 存储 |
| `updated_by` | `BIGINT` | `NOT NULL` | 最后修改人 |
| `updated_at` | `TIMESTAMPTZ` | `NOT NULL default now()` | UTC |
| `is_deleted` | `SMALLINT` | `NOT NULL default 0` | 逻辑删除 0/1；MyBatis-Plus 逻辑删除列 |
| `version` | `INTEGER` | `NOT NULL default 0` | **仅乐观锁**（内容版本一律用 `content_version`，P1-2） |

### 一·附 追加型表公共列裁剪（P1-1）

下列表**仅追加、不更新/删除**，不建 `updated_by/updated_at/is_deleted/version`（避免与 MyBatis-Plus 自动填充、"仅追加"语义冲突）；保留 `id / tenant_id（业务表）/ created_by / created_at`：

`sys_audit_log`｜`sys_event_consume_log`｜`cus_followup`｜`cus_opportunity_history`｜`cus_lead_assignment`｜`dt_raw_customs`｜`dt_raw_company`｜`dt_raw_search_trend`｜`mkg_email_record`｜`ag_task_trace`｜`ana_alert`｜`ana_nlq_log`

> 白名单追加型表（`dt_raw_*`）无 `tenant_id`，仅保 `id / created_at`。分域字典这些表的表头须标「追加型」。
> 审计类表 `sys_audit_log` 以 `actor_type`（E1）表达行为主体，**不再挂 `source_type` 来源标记列**（值域相同，P1-13 去重）。

## 三、来源标记列（智能体可写表额外自带）

存在 `source_type` 即为「双通道同源」表：人工与智能体走同一 Application Service、同一张表。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `source_type` | `VARCHAR(10)` | `NOT NULL default 'HUMAN'` | `HUMAN` / `AGENT` / `SYSTEM`（枚举 E1） |
| `source_ref` | `VARCHAR(128)` | | 来源引用（会话号 / 报关单号 / 抓取批次等） |
| `source_agent_code` | `VARCHAR(64)` | | `source_type=AGENT` 时填智能体编码，否则 `NULL` |
| `source_task_id` | `BIGINT` | | `source_type=AGENT` 时填 `ag_task.id`，否则 `NULL` |

> **P0-5 悬空引用处理**：`source_task_id` 逻辑指向 L3 智能体域的 `ag_task.id`（字段级见《字段级数据字典-10-智能体》，Wave 3 已建模）。跨产品/跨批次边界不变：**A1 阶段不加物理外键**（P0-A 拆分边界 3），以新 Flyway 脚本补约束。此引用标注为「逻辑引用，非缺陷」。

## 四、类型口径（强制）

| 语义 | 类型 | 规则 |
|---|---|---|
| 主键 / 外键 | `BIGINT` | 雪花；跨模块只存 ID，不建物理外键约束（靠应用 + 事件保证） |
| 业务编码 | `VARCHAR(n)` | `biz_code` / `xxx_code`，配唯一索引 `(tenant_id, code) WHERE is_deleted=0` |
| 金额 | `BIGINT` | **最小货币单位（分）整数**；禁止 `double/float/BigDecimal` 存金额 |
| 币种 | `CHAR(3)` | ISO-4217，引用 `cc_currency.code`（快照存储，不 JOIN） |
| 汇率 | `NUMERIC(18,8)` | 汇率是「比值」非金额，允许 `NUMERIC`；业务表存**下单/成交时点快照值** `exchange_rate`，不回查历史 |
| 日期（无时刻） | `DATE` | 如预计成交日、到港日 |
| 时刻 | `TIMESTAMPTZ` | UTC 存储，展示层按用户时区转换 |
| 多语言文本 | `JSONB` | `{"zh-CN":"…","en-US":"…"}`；前端按 locale 取值 |
| 半结构化 | `JSONB` | 明细 / 快照 / 规则体；超大高频列表拆附表（见总览§七） |
| 布尔 | `BOOLEAN` | `is_` / `has_` 前缀 |
| 状态 / 枚举 | `VARCHAR(32)` | 存**语义码**（见 §5），登记到 `sys_dict`，前端映射 i18n key；禁止裸数字码 |
| 评分 / 置信度 | `SMALLINT` / `NUMERIC(4,3)` | 0-100 整数分用 `SMALLINT`；0~1 概率用 `NUMERIC(4,3)` |

## 五、命名、索引与分区规范

- **表名**：`{域}_{实体}`，域前缀 `sys/cc/dt/cus/prd/ord`（Wave 0 主干）+ `mkg/svc`（合规触达与会话，见 06/07）+ `intel/ana/ag/kc/wb/rw`（Wave 3 六域，见 08~12）；全小写下划线。归口元枢的表（自主度策略/注册/提示词/知识引擎，`com.yuanshu.*`）不在本前缀集内建，仅以 `*_ref` 逻辑引用。
- **索引四标记**（分域字典表头）：`租户`=是否有 `tenant_id`；`RLS`=是否开行级安全；`来源`=是否有来源标记列；`分区`=是否分区。
- **唯一索引**：一律 `UNIQUE(tenant_id, …) WHERE is_deleted=0`；白名单表用业务列全局唯一。
- **外键列建索引**；区分度高的列在前；**单表索引 ≤ 5**。
- **禁止**拼接 SQL、`SELECT *`；自定义 SQL 必须手写 `tenant_id` 条件。
- **分区**：行为 / 日志 / 明细大表按月 `PARTITION BY RANGE (时间列)`，配 PG 17 原生分区。
- **全文检索**：实体名称 / 域名用 `pg_trgm` GIN 索引；向量表（kc，本期未建模）带 `tenant_id` 进索引条件。
- **事件命名**：`lx.{域}.{实体}.{动作}`，经 `sys_outbox` 发布，消费幂等。
