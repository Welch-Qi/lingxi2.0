# 灵犀 2.0 · 字段级数据字典 · 12 工作台与角色工作台（L4：`wb_` / `rw_`）

> **版本**：V0.1 草案（待评审）｜2026-10-12｜任务：M0000-008（Wave 3 六域补全）
> **前置**：公共列、来源标记列、类型口径、枚举 `E{n}`、追加型豁免见《字段级数据字典-00-公共约定.md》。
> **来源依据**：《功能清单V2.1》统一工作台（WB）、角色工作台（RW-01~05）、个性化（UW-03/21）。
> **定位**：工作台是**聚合层**，不产生新事实——待办/KPI 均由各域数据聚合而成的**派生视图**；仅**布局配置**与**用户偏好**落库。配置表为租户私域（`租户=是｜RLS=是`）。
> **复用红线**：通知复用 `sys_message`（01 文件，**E11**），**不新建通知表**；KPI 复用 `ana` 物化视图与 `dt_metric_definition` 指标口径。

---

## 一、派生视图（聚合，不落事实表）

### 1.1 `v_wb_todo` · 统一待办视图
> 跨域聚合各域的"该某人处理的事"，是工作台首页待办列表的唯一出口。**各域仍是事实权威，本视图只投影不物化**。
| 待办来源 | 底表 | 过滤条件 | `todo_type`（输出列） |
|---|---|---|---|
| 线索分配/领取 | `cus_lead` + `cus_lead_assignment` | 待分配 / 待跟进（**E25/E26**） | `LEAD` |
| 内容/开发信待审 | `ag_pending_review`（status=`PENDING`）/ `mkg_content`（status=`REVIEW`） | 智能体产出待人工审（UW-24） | `REVIEW` |
| 经营预警 | `ana_alert` | `status IN (NEW,ACKNOWLEDGED)`（**E75**） | `ALERT` |
| 情报关键词预警 | `intel_keyword_watch` 命中 | `lx.intel.keyword.changed` 落地 | `INTEL` |
| OTD 延期 | `ord_otd_node` | `node_status=DELAYED`（**E36**） | `OTD` |
| 客服工单 | `svc_session` | `status=PENDING_HUMAN/HUMAN_HANDLING`（**E52**） | `TICKET` |
| 社媒授权到期 | `mkg_social_account` | `auth_status=EXPIRING/EXPIRED`（**E68**） | `ACCOUNT` |

输出统一列：`tenant_id`、`todo_type`、`biz_ref_type`、`biz_ref_id`、`title`、`level`（E30，可空）、`assignee_user_id`、`due_at`（可空）、`created_at`。
> 视图**不带自身状态机**——完成态回落到各底表；点击待办跳源对象处理。

### 1.2 `mv_rw_kpi` · 角色工作台 KPI 卡物化视图
> 复用 `mv_ana_*`（09）与 `dt_metric_definition`（**E21**）口径，按角色圈定展示的指标子集。列：`tenant_id`、`role_code`、`metric_code`、`metric_value`、`unit`、`period`、`mom_growth`。不落独立事实。

## 二、角色工作台配置（`rw_workbench_config`）

### 2.1 `rw_workbench_config` · 角色工作台布局/卡片配置〔P0-A〕
> 租户:是｜RLS:是｜来源:否｜分区:否　（RW-01~05 + 个性化 UW-03）
> 五类角色（管理/销售/市场/客服/供应链…）默认工作台布局；租户/角色可覆写。布局以 `layout_json` 承载（卡片顺序/显隐/宽度），不逐卡片建表。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `role_code` | `VARCHAR(32)` | `NOT NULL` | 角色（关联 `sys_role`，RW-01~05 语义码） |
| `name` | `VARCHAR(128)` | `NOT NULL` | 配置名 |
| `layout_json` | `JSONB` | `NOT NULL` | 卡片布局（待办/KPI/图表清单 + 顺序/显隐/栅格） |
| `kpi_metric_codes` | `JSONB` | | 该角色默认 KPI 指标码数组（引用 `dt_metric_definition`） |
| `todo_types` | `JSONB` | | 订阅的待办类型（`v_wb_todo.todo_type` 子集） |
| `is_default` | `BOOLEAN` | `NOT NULL default false` | 是否角色默认（租户覆写时同 `role_code` 多行，`is_default` 取权威行） |
| `owner_user_id` | `BIGINT` | | 个性化归属（空=角色级默认，非空=用户覆写，配合 `rw_user_preference`） |
| `status` | `VARCHAR(16)` | `NOT NULL default 'PUBLISHED'` | **E41** |

索引：`UNIQUE(tenant_id, role_code, owner_user_id) WHERE is_deleted=0`、`(role_code, is_default)`。

## 三、用户偏好（`rw_user_preference`）〔B〕

### 3.1 `rw_user_preference` · 用户偏好/多岗视图切换
> 租户:是｜RLS:是｜来源:否｜分区:否　`[B]`（UW-21）
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `user_id` | `BIGINT` | `NOT NULL` | → `sys_user.id` |
| `pref_key` | `VARCHAR(64)` | `NOT NULL` | 偏好项（当前岗位视图/常用角色/主题密度…） |
| `pref_value_json` | `JSONB` | `NOT NULL` | 偏好值（多岗切换的活动角色、默认工作台等） |

索引：`UNIQUE(tenant_id, user_id, pref_key) WHERE is_deleted=0`。
> UW-21 多岗：一人可属多角色，`pref_key='active_role'` 存当前切换视图；权限并集仍由 `sys_data_scope`（E6/E7）裁决，本表只存 UI 偏好不放权。

## 四、状态机落点

| 对象 | 表 | 状态字段 | 枚举 | 迁移事件 |
|---|---|---|---|---|
| 工作台配置 | `rw_workbench_config` | `status` | **E41** | 无独立事件（配置变更走 `sys_audit_log`） |

> 本域**不新增领域事件**（消费他域事件聚合为待办）；`v_wb_todo` 各待办由源域事件驱动刷新（`lx.ana.alert.raised`、`lx.ag.task.needs_human`、`lx.mkg.account.auth_expiring`、`lx.intel.keyword.changed` 等）。

## 五、跨域与归口约束

- **聚合引用**：`v_wb_todo` 投影自 `cus_lead`/`ag_pending_review`/`mkg_content`/`ana_alert`/`intel_keyword_watch`/`ord_otd_node`/`svc_session`/`mkg_social_account`——**只读、不物化、不改写源表状态**。
- **通知复用**：待办触达/预警推送复用 `sys_message`（01，**E11** `TASK`/`ALERT`），不新建通知表。
- **指标复用**：`mv_rw_kpi` 复用 `mv_ana_*`（09）+ `dt_metric_definition`，KPI 口径唯一来源不在本域重定义。
- **权限边界**：`role_code`/多岗视图仅决定 UI 呈现；数据可见范围由 `sys_data_scope`（E6/E7）+ RLS 决定，配置表不得扩权。
- **事件命名**：本域无 `lx.wb.*` 新增事件（硬约束 3 下消费他域事件）。

## 六、待决策项（留人工裁决）

1. **`v_wb_todo` 是否物化**：跨 8+ 底表聚合，纯视图在大租户下可能慢——是否转 `mv_wb_todo` 增量物化（随源域事件刷新），待性能评估。
2. **角色工作台与权限模型边界**：`rw_workbench_config.role_code` 与 `sys_role` 是否一一对应，多岗并集视图如何合并展示，待 04-tenant/RBAC 定稿对齐。
3. **`layout_json` 结构规范**：卡片 DSL 的 schema 是否需要平台统一约束（避免前端各页自定义漂移），待前端契约（下一轮 03-api）确认。
