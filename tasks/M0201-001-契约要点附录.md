## 三、探针链路（用户裁决「两者都做」的第二半，已验证）

改动 3 处，其中 2 个新文件命中**红线①（认证与会话）**，**须人工 Review 才能合并**：

| 文件 | 改动 |
|---|---|
| `com/yuanshu/sys/security/YuanshuSecurityProperties.java`（新） | 绑定 `yuanshu.security.{oidc-enabled,issuer-uri,jwk-set-uri}`。此前这些键在 yml 里写了很久却**没有绑定类**，配置不生效，认证退化为 Boot 默认全量拦截 |
| `com/yuanshu/sys/security/PlatformSecurityConfig.java`（新，**红线①**） | 探针 `permitAll` + 其余 `authenticated`；`oidc-enabled=true` **且** URI 非空才装配资源服务器，否则 fail-closed 并告警 |
| `yuanshu-starter-security/.../TenantContextFilter.java`（**改**） | `shouldNotFilter()` 跳过 `/actuator/health*`、`/actuator/info` —— 该 Filter `@Order(HIGHEST+20)` 且 `reject-missing-context=true`，不跳过则探针被 403 |

实测（`start-dev.sh` 拉起后）：

| 请求 | 状态码 | 判定 |
|---|---|---|
| `GET /actuator/health`（无 token） | **200** `{"status":"UP","groups":[…]}` | 探针放行，`check-env.sh` 第 4 层与 `start-dev.sh` 就绪等待均通过 |
| `GET /actuator/health/liveness` | 200 `{"status":"UP"}` | 同上 |
| `GET /actuator/metrics`（无 token） | 401 | 内部指标不对外的 fail-closed |
| `GET /api/v1/cus/customers/1`（无 token） | 401 | 业务端点要求认证 |
| 同上 + `Authorization: Bearer a.b.c`（伪造） | 401 | 验签生效，未放行 |

`check-env.sh` 现报「环境体检全部通过」且 **后端在跑时仍为 exit 0**（此前只能靠停进程转绿）。
启动日志确认装配：`SEC|oidc|resource-server enabled|jwks=configured issuer=configured`。
