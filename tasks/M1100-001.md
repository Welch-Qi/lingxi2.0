### 1.1 向量底座已就绪 —— **不必等 `kc_*` 表**

`dt_knowledge_embedding`（**dt 域，已建**）已具备完整向量能力：

```
embedding :: vector(1024)          ← pgvector 0.8.7 已装
CREATE INDEX idx_dt_embedding_hnsw ON dt_knowledge_embedding
```

→ **本任务可基于 `dt_knowledge_embedding` 直接实现混合检索，不必先建 `kc_*` 表。**

## 二、任务范围（IN SCOPE）

### 2.1 契约（若 M0201-001 已含 `kc/knowledge/search` 则只核对，不重复写）

`GET /api/v1/kc/knowledge/search?keyword=&locale=&limit=`
- 权限码：`kc:knowledge:search` 或复用现有 `kc:*` 策略（**先查 `casbin/lingxi_policy.csv`**
  现有 24 条策略，无匹配则在待决策提出，勿自建）
- 响应：`R<List<SearchHit>>`，每项含 `objectType` / `objectId` / `score` / `snippet` / `locale`
- **必须可按租户过滤**（套件 ③ 断言「A 的检索不得召回 B 的记录」）

### 2.2 实现（`com.lingxi.kc` 四层，规约 §4.1）

| 层 | 内容 |
|---|---|
| `domain` | `KnowledgeRepository` 接口 + 检索条件对象（**禁 Spring/MyBatis 类型**） |
| `infra` | MyBatis-Plus Mapper（`dt_knowledge_embedding`）+ 仓储实现 |
| `app` | 检索编排：权限校验 → 租户过滤 → 混合检索 → 响应组装 |
| `api` | Controller + DTO（`R<T>` / 分页结构） |

### 2.3 混合检索（向量 + 模糊，规约 §4.6 与 M1200-005 口径）

- **向量段**：HNSW 索引已建 → `ORDER BY embedding <=> :queryVector LIMIT n`（cosine）
  - 向量来源：调用模型网关的 embedding 接口（`config/model.yml` 的 `model-embedding`）
  - ⚠️ **本地无真实模型网关** → 本任务须**支持降级**：网关不可用时退化为纯 `pg_trgm` 模糊检索，
    并在响应中标注 `mode: "fallback"`（对应 `model.yml` 的 `fallback.rule-fallback-enabled: true`）
- **模糊段**：`pg_trgm` 的 `similarity()` + `gin_trgm_ops` 索引
- **合并**：两段结果按分数归一化后合并去重（具体算法写进待决策，由人工定标）

### 2.4 租户隔离（**本任务最易踩空处**）

`dt_knowledge_embedding` 已开 RLS（23 张已建表之一），应用侧由
`YuanshuRlsSessionInterceptor` 写 `app.tenant_id` 会话变量实现。
→ **必须实测：租户 A 检索时看不到租户 B 的向量记录。**
若返回 0 行 → 检查 `TenantContextFilter` 是否已注入租户上下文。

### 2.5 顺带：02-data 10 篇表名订正

把上表 1.3 的表名差异订正，并在该篇版本记录追加一行说明（格式参照既有 V0.x 行）。
