### 2.2 每张表的强制要求（**踩过坑，务必照做**）

1. **公共列齐全**（技术规约2.0 §4.4.1，参照 `sys` 基线脚本的写法）：
   `id BIGINT NOT NULL`（雪花 ID，**禁 UUID / 禁自增**）、`tenant_id BIGINT NOT NULL`、
   `created_by` / `created_at` / `updated_by` / `updated_at` / `is_deleted` / `version`
2. **RLS 必须开**：`ALTER TABLE <表> ENABLE ROW LEVEL SECURITY;` +
   `CREATE POLICY p_<表>_tenant ON <表> USING (tenant_id = sys_current_tenant())`
   —— 23 张已建表**全部**如此，谓词**必须逐字一致**（本仓统一写法，见
   `sys_current_tenant()` 定义）
3. **部分唯一索引用 `WHERE is_deleted = 0`**，例：
   `UNIQUE(tenant_id, biz_code) WHERE is_deleted=0`（`cus_customer` 的 biz_code / entity_id）
   —— ⚠️ **不要同时建表级 `UNIQUE` 约束**：表级约束不区分 `is_deleted`，
   会导致「软删除后无法重建同名记录」。这是 `dt_account_asset` 的真实缺陷，
   已被 `V202610201100` 修复（见 02-data V0.8 记录），**不要重犯**。
4. **索引按 02-data 各节的「索引：」行逐条落地**，注意 `cus_customer` 的
   `(tier, stage)` 复合索引 —— **V2.1.1 已停用 `stage`**，
   该索引应按 02-data 说明**退化为 `(tier)`**
5. **时间用 `TIMESTAMPTZ`**（规约：UTC 存储）
6. **JSONB 长尾列**用 `ext_json JSONB`
7. **枚举列用 `VARCHAR`** + 值集注释（**不建 PG enum 类型**，与既有 44 张表一致）
8. **每列加 `COMMENT ON COLUMN`**，每表加 `COMMENT ON TABLE`（含来源章节引用）
9. **`stage` 列**：V2.1.1 已停用 —— 字段保留但**注释必须写明「已停用、新代码不得读取」**
