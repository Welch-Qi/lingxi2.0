## 一、背景与关键事实（**执行前必读**）

隔离套件 ④「智能体层」依赖 `POST /api/v1/ag/tools/invoke`：
**智能体以租户 A 的上下文调用工具 → 不得读取租户 B 的数据**。
`lingxi-agent` 模块**只有 5 个 `package-info.java`**，无任何实现。

### 1.1 工具注册表已就绪 —— `ag_skill_registry`（**已建表，17 列**）

```
id / tenant_id / skill_id / name(jsonb) / domain / tool_name / version_no
perm_codes(jsonb) / high_risk / outbound / requires_approval
autonomy_max / timeout_ms / retry_policy / tenant_scope / mcp_server
```

这套字段已覆盖工具调用所需的全部判定维度（权限码、高危标记、是否外发、是否需审批、
自主度上限、超时、重试、租户范围、MCP 服务器）→ **本任务不需建表**。

### 1.2 Casbin 策略已存在 —— `SUB_AGENT_CUS`

```
p, SUB_AGENT_CUS, cus:lead:create,  access, DEPT
p, SUB_AGENT_CUS, dt:entity:search,  access, ALL
p, SUB_AGENT_CUS, mkg:email:draft,   access, ALL
```

→ 隔离套件 ④ 用的 `skillId: "cus.customer.query"` **不在现有策略中**，
本任务需在契约里对齐一个**已有的** `skillId`（见待决策 1）。

### 1.3 ⚠️ 顺带订正文档口径漂移

## 二、任务范围（IN SCOPE）

### 2.1 契约（若 M0201-001 已含 `ag/tools/invoke` 则只核对）

`POST /api/v1/ag/tools/invoke`
```json
{ "skillId": "<已注册的 skill_id>", "params": { ... } }
```
- 权限码：以 `ag_skill_registry.perm_codes` 为准，**逐条经 Casbin 决策**
- 响应：`R<ToolInvokeResult>`，含 `skillId` / `output` / `cost`（token）/
  `requiresApproval` / `approvalId`（需审批时）
- **失败语义**：权限不足 → 403；工具不存在 → 404；需人工审批 → 200 + `requiresApproval=true`
  （**不是**直接失败 —— 自主度模型下「先审批再执行」是正常路径）

### 2.2 实现（`com.lingxi.ag` 四层，规约 §4.1）

| 层 | 内容 |
|---|---|
| `domain` | `SkillRegistry`（读 `ag_skill_registry`）、`ToolExecutor` 接口、工具上下文 |
| `infra` | Mapper + 仓储实现；**至少实现 1 个具体工具**（见 2.3） |
| `app` | 调用编排：查注册表 → Casbin 权限决策 → 自主度判定 → 执行 → 审计留痕 |
| `api` | Controller + DTO |

### 2.3 至少实现 1 个可执行工具（**否则套件 ④ 无从验证**）

建议实现 `cus.customer.query`（查客户详情）—— 与隔离套件 ④ 的断言直接对应：
> 智能体以租户 A 上下文调用工具，**不得读到租户 B 的客户数据**。

工具实现**必须走同一套 Application Service**（AGENTS.md 铁律 2「双通道同源」：
人工操作与智能体执行走同一个 Service、同一张表，**禁止** `/api/agent/**` 影子写接口）。

### 2.4 自主度与人工审核（**红线区域，务必严格**）

AGENTS.md 铁律 4 + 技术规约 §4.7：

| 判定字段 | 规则 |
|---|---|
| `outbound = true` | **禁止**配 A2/A3 自主度（必须人审） |
| `high_risk = true` | 强制人审 |
| `requires_approval = true` | 返回 `requiresApproval=true` + 生成审批单（`ag_approval_request` 已建表） |
| 价格 / 合同 / 赔偿 / 投诉 | 强制 **A0**（人工主导） |
| `autonomy_max` | 调用方自主度不得高于注册表声明的上限 |

> ⚠️ **这三条属红线**：命中即停止自动合并，转人工 Review（AGENTS.md 铁律 10）。

### 2.5 租户隔离（**本任务核心断言**）

- 调用时 `TenantContext` 已由 `TenantContextFilter` 注入（从 JWT 的 `tenant_id` claim 取，
  并与 `X-Tenant-Id` 头比对）→ 工具内部的 DB 查询自动受 RLS 约束
- **必须实测**：智能体以租户 A 上下文调用 `cus.customer.query` 查租户 B 的客户 ID → 查不到
