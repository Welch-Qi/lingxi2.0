## 二、任务范围（IN SCOPE）

在 `lingxi-docs/03-api/灵犀系统多产品API契约-1.0.md` 中补齐**客户中心**接口契约，
使隔离套件 ①~⑤ 所需的每个端点都有明确的请求/响应定义。

### 2.1 必选端点（覆盖隔离套件 ①~⑤ 的直接依赖）

| 端点 | 用途 | 套件项 |
|---|---|---|
| `GET /api/v1/cus/customers/{id}` | 单客户详情 | ① 数据层越权 |
| `GET /api/v1/cus/customers?pageNo&pageSize` | 客户列表（响应须含 `tenantId`） | ② 列表层归属 |
| `GET /api/v1/cus/customers/export?format=csv` | 客户导出（CSV） | ⑤ 导出对账 |
| `GET /api/v1/kc/knowledge/search?keyword` | 知识检索（含向量） | ③ 检索层 |
| `POST /api/v1/ag/tools/invoke` | 智能体工具调用 | ④ 智能体层 |

> ② 项断言列表响应含 `tenantId` 字段 —— **契约必须明确该字段**，否则隔离脚本无法断言。
> 这一条是 03-api 对本次实现最关键的约束。

### 2.2 应选端点（客户中心最小可用集）

依据 02-data 03 篇已定义的 9 张表（`cus_customer` / `cus_contact` / `cus_lead` /
`cus_lead_assignment` / `cus_opportunity` / `cus_opportunity_history` / `cus_followup` /
`cus_tag_relation` / `cus_health_score`），补齐对应 CRUD 契约：

- `GET|POST /api/v1/cus/customers`
- `GET|PUT|DELETE /api/v1/cus/customers/{id}`
- `GET|POST /api/v1/cus/leads`、`GET|PUT /api/v1/cus/leads/{id}`
- `GET|POST /api/v1/cus/opportunities`、`GET|PUT /api/v1/cus/opportunities/{id}`
- `GET|POST /api/v1/cus/followups`
- `GET /api/v1/cus/customers/{id}/contacts`

### 2.3 每个端点必须写明

1. **路径与方法**（遵循 §二：`/api/v1/{产品}/{域}/{资源复数}`，单数仅用于 `search`/`export` 等动作）
2. **权限码**（`cus:customer:view` / `cus:lead:create` / `cus:opportunity:*` 等，与 `casbin/lingxi_policy.csv` 现有 24 条策略对齐 —— 现策略已含 `cus:*` 系列，**不得新增冲突权限码**）
3. **请求头**（§三：必带 `X-Tenant-Id`、`X-Trace-Id`、`Authorization`）
4. **请求参数**（路径 / query / body，分页参数 `pageNo`/`pageSize`，`pageSize` 上限 200）
5. **响应体**（§四.1 `R<T>` 结构；列表用 §四.2 分页固定结构 `{ list, total, pageNo, pageSize }`）
6. **数据权限 scope**（SELF / DEPT / DEPT_AND_SUB / ALL，取自 Casbin 策略的 scope 维度）
7. **错误码**（§五 6 位 `AABBCC`）
8. **幂等要求**（写操作：是否需 `X-Idempotency-Key`，按 §4.3.3 判定）
9. **字段映射**：响应字段 ↔ 02-data 03 篇的列定义（**响应体不得直接暴露敏感列**，如凭证类）
